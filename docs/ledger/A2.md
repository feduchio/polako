# A2 — Domain: schemas, FSM tables, invariant + property tests

## Contract

Scope: `src/domain/**`, `src/shared/**` (pure; no I/O, no imports outside `domain/` and `shared/`).

Acceptance criteria:

1. `pnpm check` passes (typecheck strict, eslint strictTypeChecked, dependency-cruiser, vitest).
2. Run state is two orthogonal axes: `RunPhase` table and `RunControl` table + `applyControlCommand`.
   Every `(control, command)` pair yields a state, and every actual change is an edge in `RUN_CONTROL_TABLE`.
   `kill` is absorbing; `stop` is irreversible; only `RUNNING` dispatches jobs.
3. `RunPhase` ordering enforces: `INTERPRETING_MISSION` only after `BASELINING`; `REVIEWING` is entered
   only from `REVIEW_ENTRY_PHASES` = {INTEGRATING, PLANNING, CONVERGENCE_CHECK} — never from
   COMPARING/GATING/EXECUTING (a winner must be integrated before review; PLANNING→REVIEWING serves
   missions with no coding requirements; CONVERGENCE_CHECK→REVIEWING starts the next clean round on an
   unchanged checkpoint); `INTEGRATING` is the only code-changing phase and is entered only from
   `COMPARING`; `SIMPLIFYING` only plans `simplify` tasks (→ EXECUTING) or finds nothing (→ CONVERGENCE_CHECK)
   and can never reach GATING/COMPARING/INTEGRATING/REVIEWING/DONE directly; `DONE` only from `CONVERGENCE_CHECK`.
   *(Contract wording revised after verifier round 1 — see F1/F2.)*
4. Every transition table passes `validateTable` (reachability, closed terminals, no dead ends).
5. Task origin is a closed discriminated union `valid_finding | mission_requirement | investigation`;
   the `valid_finding` branch can only carry the literal `verdict: "VALID"`. `createTaskFromValidFinding`
   throws for any finding status other than VALID, for non-blocking findings, and for a validation that
   does not belong to the finding or is not VALID. Investigation tasks come only from UNCERTAIN findings,
   are bounded by `maxRounds`, and have `touchesProductCode=false` (schema-enforced).
6. `FindingValidationStrictSchema`: VALID verdict requires at least one evidence artifact.
7. Facts carry `provenanceKind ∈ {user_stated, deterministic, llm_inferred, verified}`. `verified`
   requires non-empty `evidenceRefs`; `deterministic` has `confidence: null`; `promoteToVerified`
   is the only promotion path and accepts only `llm_inferred` facts.
8. `EvidenceVector` comparison `dominates` is a strict partial order (irreflexive, asymmetric,
   transitive) and never trades a broken test for a fixed finding.
9. Clean rounds are keyed by `checkpointHash`; `hasConverged` counts only rounds for the given hash.
   Novelty (`isNovelRound`) is informational.
10. `compareToBaseline` treats baseline failures as non-regressions, flags newly failing tests,
    degraded checks, and a reduced test count (possible silencing).
11. `Mission` is hashed over `projectPath/text/userConstraints/userDecisions`; `missionIsIntact` detects tampering.
