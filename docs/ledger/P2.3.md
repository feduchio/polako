# P2.3 — Discovery smoke on a second repository

**Status:** FROZEN, revision 1. **Base:** HOST `d25c78f`.
**Plan reference:** `docs/PLAN.md` §4 P2.3. **Goal:** G2. **Process:** v3.

`docs/PLAN.md` §2 records **0** external projects ever targeted. This item makes that 1, for the
first two phases only. It is explicitly **not** Fable D1: the full external run is not scheduled in
this document, and nothing here licenses one.

The repository was left unnamed by the user at execution time, so the plan's stated fallback
applies: a clean clone of a small public TypeScript repository with a working `pnpm test`.

## Mandatory clauses

**MC1 — the repository is qualified before Polish touches it.** The exact clone URL and commit hash
are recorded. On a clean clone, `pnpm install` and `pnpm test` are run **first**, and their results
recorded. A repository whose `pnpm test` is not green on a clean clone is **rejected**, and the
rejection is recorded with its reason rather than worked around — a baseline snapshot of a failing
suite would make the smoke meaningless. The clone lives outside the Polish tree and is not
committed.

**MC2 — the daemon under test is built from the commit under review.** A daemon built from an
earlier branch is currently running; it is stopped before the smoke, with `SIGTERM` and never
`SIGKILL`, and its identity is recorded so it is clear what was replaced. The daemon used for the
smoke is built from this item's base, and its build path and commit are recorded. A smoke run
served by a stale daemon measures code that is not under review.

**MC3 — the run goes through the production CLI and stops where the plan says.** The run is created
with `polish run <repo> --runtime off`, not by patching the store. It must reach
`DISCOVERING_PROJECT` and then `BASELINING`. It is stopped as soon as it leaves `BASELINING`, and
the **observed phase sequence is recorded verbatim from `run.phase_changed` events**, not
summarised. If the run advances further than intended before the stop lands, the record states how
far and what it cost; it does not claim a cleaner stop than happened.

**MC4 — what `BASELINING` actually captured is quoted, not asserted.** The recorded baseline —
the check results snapshotted for the external project — is read back from the store and quoted.
"It reached `BASELINING`" without showing what the baseline contains would not distinguish a real
discovery from a phase transition.

**MC5 — P2.1's population must be re-verified, because this run writes to the same store.**
`scripts/p2-1-yield.mjs` is re-run after the smoke and must still report **0** eligible
executions and MC5 of `docs/ledger/P2.1.md`'s four figures — 209 reviewer calls, 83 with
`usage: null`, 834,635 attributed tokens, 18 completed review executions. The smoke must not reach
review, so those numbers must not move. **If any of them moves, that is recorded as a change to
P2.1's measured population**, with the new values, rather than left for a later reader to discover.

**MC6 — no production change, and no scope beyond the smoke.** No code under `src/` changes. No
mission is executed to completion, no task is planned, no external run is scheduled, and the
registered-projects list is left in whatever state the CLI puts it — recorded, not curated.

**MC7 — free-tier only.** `routing.costEligibility` stays `free_only`. Any model call the two
phases issue is recorded with its role and purpose. If the stop lands after a council call, its
token cost is recorded.

## Acceptance criteria

1. The clone URL, commit, and the pre-Polish `pnpm install` / `pnpm test` results are recorded.
2. The stopped daemon and the daemon under test are both identified, with the build commit of the
   latter.
3. The verbatim phase sequence from `run.phase_changed` is in the record, with the stop point.
4. The baseline the run captured is quoted from the store.
5. The four P2.1 figures and the eligible count are re-stated after the smoke, with any movement
   called out as movement.
6. Any model calls issued are listed by role and purpose with their token cost.
7. The record states plainly that this is not Fable D1 and that no external run is scheduled.
