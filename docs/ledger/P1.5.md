    10|efficiency, not a quality claim"**. It was measured on reviewers. This item asks whether the same

## Mandatory clauses

**MC1 — one configuration field, defaulting to today's behaviour.**
`routing.disableReasoning: boolean`, default **`false`**, on `RoutingConfigSchema`
(`src/domain/config.ts:151-156`). At the default, a worker request and a council request must be
**byte-identical to what they are at base** — in particular `reasoning` must be `undefined`, not a
    30|key with a falsy value, because `openaiCompat` forwards the field whenever it is not `undefined`
(`src/providers/openaiCompat.ts:74`) and a provider that sees `{"reasoning": null}` is not seeing
the base request.

`routing` is the section that already holds cross-cutting model-cost policy
(`costEligibility`, the price ceilings). Reasoning effort is a cost lever applied at request
construction, so it belongs there rather than in `agent`, which is worker-only, or in `council`,
which is retry policy. One field and not two, because the experiment's arm is the pair of sites
together and a second field would only ever be set to the same value as the first.

**MC2 — one function, applied at both sites.** A single exported helper decides the field, so the
    40|two sites cannot drift:

```ts
withConfiguredReasoning(request: CompletionRequest, disable: boolean): CompletionRequest
```

It returns `request` unchanged when `disable` is `false`, **and also when the request already
carries a `reasoning` of its own**. The second case matters: the reviewers and the progress tracker
set `DISABLED_REASONING` deliberately, and a policy flag that silently overwrites a site's explicit
choice would make a future disagreement invisible. Today no request reaching either site carries
one, so the clause is about what the code permits, not about current behaviour.

    50|**MC3 — the worker site.** `createWorkerFactory` wraps the broker in `complete:` at
`src/daemon/composition.ts:805`. That wrapper is the seam, and the helper is applied there, reading
`deps.config.routing.disableReasoning`. `AgentRunner` is not given a new option: it does not
construct the reasoning field today and giving it one would put the decision in two places.

**MC4 — the council site.** `CouncilRoleConfig` (`src/council/types.ts:15-20`) gains
`disableReasoning?: boolean`, `CouncilRoleAgent.analyze` applies the helper to the request it builds,
and `resolveCouncilRoles` (`src/daemon/composition.ts:901-958`) passes
`deps.config.routing.disableReasoning`. All three roles, not one.

**MC5 — nothing else changes.** `swarm.ts` and `progressTracker.ts` keep their unconditional
    60|`DISABLED_REASONING` and are not routed through the flag, and neither does `capabilityProbe.ts`:
setting the flag to `false` must not turn reviewer reasoning back on. No other call site gains the
field — the finding debate and the model audition in particular.

**Revision 2:** this clause is now observed rather than asserted. "No other call site gains the
field" is a statement about a diff, which only a reader can check — and a reader checked it and it
was not enough: the entry-gate lane applied the flag to `completeDebateRole` and nothing failed.
AC5 turns it into a property of a whole production run, plus a named check for each of the two
production sites that run does not reach.

**MC6 — the experiment, and its decision predicate.** Three fixture runs per arm on
`fixtures/resume-dup-fetch`, models pinned in `docs/ledger/P1.5-run.md`. The default changes **only
if both halves hold**:

1. the multiset of task **titles** reaching `INTEGRATING` is identical in all three runs of both
   arms — titles, not ids, because ids carry random bytes (`src/shared/ids.ts:17-31`) and can never
   compare equal across runs; **and**
2. total tokens are lower in the disabled arm in **all three** runs.
    70|
If the fixture is not that deterministic across three runs, the result is
**`inconclusive — fixture nondeterministic`** and the default does not change. An arm that cannot be
run to completion at all is reported as such, with the reason, and is also `inconclusive`. A partial
or fabricated arm is not a result.

**MC7 — the flag stays `false` on acceptance regardless.** Even a passing predicate does not flip
the default inside this item: `docs/PLAN.md` §1's quality-coupling clause forbids enabling a
cost-reducing behaviour by default while the quality gate is not `pass`, and it is not. A pass here
authorises a separate one-line commit after P2.2, exactly as P1.1's skip flag does.

    80|## Acceptance criteria

**AC1 — the default is the base request, and that is more than one absent key.** With
`defaultConfig()`, a worker request and a council request both have `reasoning === undefined` and
`"reasoning" in request === false` — the second because a key present with an undefined value
serialises differently through the provider payload builder.

**Revision 2:** and the request's **whole key set** is pinned, in both arms. Revision 1's AC1 looked
only at `reasoning`, so the entry-gate lane added `temperature: 0.25` inside the worker wrapper and
every check passed. MC1's claim is that the default request is what it is at base, and a criterion
that observes one field of it does not observe that claim. The worker's keys are the five
`AgentRunner` builds (`src/agents/runner.ts:86-98`); the council's are the five
`CouncilRoleAgent.analyze` builds.

**AC2 — the helper, all four input classes.** `withConfiguredReasoning` is checked on each of:
`disable=false` with no reasoning → unchanged and **the same object reference**;
`disable=false` with a reasoning → unchanged; `disable=true` with no reasoning → a **new** object
carrying `DISABLED_REASONING` and the original **not mutated**; `disable=true` with a reasoning of
    90|its own → unchanged, same reference. Four cases because each is a different branch and a
one-case check passes for three wrong implementations.

**AC3 — the worker site is wired, observed at the provider.** A run built through
`buildProductionDeps` with `routing.disableReasoning: true` produces a worker `model.call` whose
request carries `{ effort: "none", exclude: true }`; with the default it carries no `reasoning`.
Observed on what the **provider** received, not on the helper's return value — P1.4's round 3
showed a tested function and a tested renderer do not add up to a tested report, and the call site
between them is its own surface.

**AC4 — the council site is wired, for all three roles.** Same shape, asserted for `planner`,
   100|`scope_guardian` and `judge` **each**, by iteration rather than by naming one of them. P1.4's
round 4 rule: when a clause quantifies over a set, the criterion iterates the set.

**AC5 — the sites the flag must *not* reach, observed at the pipeline (revision 2).** Revision 1
asserted this only at the unit level, where `runAxisReview` and `EmpiricalProgressTracker` never see
a config and the clause is therefore unfalsifiable. The entry-gate lane showed what that missed:
stripping the reviewer's or the progress tracker's `DISABLED_REASONING` **in composition**, and
applying the flag to `completeDebateRole`, each survived every check.

So a whole production run is driven to `DONE` through `installProductionDrivers`, in **both** arms,
and the reasoning actually sent is asserted **per role** — `worker`, `planner`, `scope_guardian`
and `judge` follow the flag; `reviewer` and `probe` do not move. The **observed role set** is
pinned as well, so a site that starts or stops calling a model changes the table and has to say so.

**AC5a — the two production sites the happy path never reaches.** The finding debate and the model
audition are production model calls outside the pipeline above, so the whole-run criterion cannot
see them. Each is asserted separately to send no `reasoning` under either arm.
`completeDebateRole` is exported for this and for nothing else; `installProductionDrivers` remains
its only caller.

**AC6 — the run record answers MC6.** `docs/ledger/P1.5-run.md` states the two pinned models, the
three run identities per arm, the multiset of task titles reaching `INTEGRATING` for each of the six
runs, the total tokens for each, and the verdict. If the verdict is `inconclusive`, it states which
half of the predicate failed and on which runs, with the observed titles, rather than asserting
   110|nondeterminism in the abstract.

**AC7 — mutation.** Each must fail a **named** check: defaulting `disableReasoning` to `true`;
applying the helper at the worker site but not the council site, and the reverse; applying it for
one council role only; overwriting a request's existing `reasoning`; mutating the input object
rather than returning a copy; routing `swarm.ts` through the flag; routing `progressTracker.ts`
through it; setting `reasoning: undefined` as a present key at the default. Added in revision 2,
each from a round-1 entry-gate finding: adding an unrelated field inside the worker wrapper;
stripping the reviewer's reasoning in composition; applying the flag to `completeDebateRole`;
applying it to the model audition.
