# A4 — Scheduler: jobs, lanes, leases, dependencies, cancellation, recovery

## Contract

Scope: `src/scheduler/**`. May import `domain/`, `shared/`, `store/`.

1. `pnpm check` passes.
2. All job state lives in the store: `job.created` / `job.state_changed` events carry full snapshots; the only
   in-memory state is the set of in-flight promises. Lease renewals (`heartbeat`) and `cancelRequested` are
   ephemeral column updates on the `jobs` projection (documented exception; recovery does not depend on them).
3. Every state change goes through `JOB_TABLE` (`assertTransition`).
4. `tick()` is explicit and deterministic given store contents: promote PENDING → READY when all deps SUCCEEDED;
   cancel PENDING whose deps FAILED/CANCELLED (cascade); reclaim RUNNING jobs with expired leases not owned by
   this process (→ READY, or → FAILED when attempts are exhausted); apply run control; dispatch READY jobs.
5. Dispatch order: priority DESC, then created_at ASC. Lane capacity from `LaneLimits` (+ per-lane overrides;
   `llm.*` lanes fall back to `llm.default`). `integration` lane capacity is 1.
6. Run control: only `RUNNING` runs dispatch (`mayDispatchJobs`); `PAUSE_REQUESTED`/`PAUSED` let in-flight jobs
   finish; `STOP_REQUESTED`/`STOPPED`/`KILLED` abort in-flight jobs via `AbortSignal` and cancel PENDING/READY.
7. Handler outcome: resolve ⇒ SUCCEEDED (result stored); throw ⇒ READY if `attempts < maxAttempts` else FAILED;
   abort ⇒ CANCELLED. A job whose row is no longer RUNNING when the handler finishes is left untouched.
8. `recover()` on startup returns RUNNING jobs with a foreign or expired lease to READY.
9. Jobs with no registered handler fail (READY → FAILED) instead of hanging.
10. `settle(runId?)` resolves only when no jobs are in flight.
