**Prompt:** actual candidates; deterministic evidence first; independent judge; transparent choice provenance.

## Required behavior

1. Tournament input is the set of candidates that **passed independent gates**. Failed-gate candidates are ineligible.
2. Ranking uses deterministic metrics first (gate vector, tests passed/failed vs baseline, diff size, silencing/protected failures already excluded by gates).
3. If more than one candidate remains after deterministic comparison, a pairwise/pivot judge (`VerifierStrategy`, TS backend in Phase B) compares survivors. Python sidecar is C3, not required.
4. Judge receives candidate diffs/gate reports/acceptance criteria — **not** other judges' opinions and not the implementer transcript as authority.
5. Output is a winner id plus provenance: metric table, pairwise verdicts, rationale artifact. Choice is reconstructible from the event log (`candidate.compared`).
6. Production `COMPARING` driver runs this tournament. Empty eligible set does not invent a winner.

## Prohibited shortcuts

- Random or first-candidate winner.
- Judging candidates that failed gates.
- LLM-only ranking that ignores deterministic metrics.
- C3 sidecar as a Phase B dependency.

## Deterministic evidence

- Metrics: candidate A dominates B on evidence vector ⇒ A wins without LLM.
- Tie + scripted judge ⇒ recorded pairwise rationale and winner.
- Zero eligible candidates ⇒ no winner, provenance says so.
- Ineligible (failed gates) candidate cannot be selected even if a fake judge prefers it.
- `pnpm check`.
