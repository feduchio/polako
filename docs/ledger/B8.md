## Required behavior

1. Semantic log renderer walks the event log using `causedBy` links (why-chain), not an invented narrative.
2. Interim report (in-progress), final report (DONE), and NEEDS_HUMAN report (question + options from `terminalReason`).
3. Final report includes: mission text, interpretation id, baseline checkpoint, task ids, candidate commits, gate summaries, winner provenance, integration checkpoint, review executions, validations, clean rounds with proof refs, runtime evidence checkpoint hashes, final diff summary vs baseline.
4. Reports are artifacts (`report.generated`) and do not mutate the user tree.
5. Production emits a final report before/as DONE (and a NEEDS_HUMAN report on that terminal).

## Prohibited shortcuts

- Reports that claim work without corresponding events.
- Why-chain that ignores `causedBy` and concatenates timestamps only.

## Deterministic evidence

- Given a fixture event sequence, renderer includes candidate commit and omits unmentioned phases.
- NEEDS_HUMAN report contains the question from terminalReason.
- Final report checkpoint hash matches run.currentCheckpointHash.
- `pnpm check`.

## Implementation notes

- `src/report/semanticLog.ts` — `SemanticEventLog.whyChain` walks `causedBy` backward and effects forward from a seed entity; unrelated events are excluded.
- `src/report/build.ts` — `buildFinalReportInput` gathers only store projections (mission, tasks, candidates, checkpoints, reviews, validations, clean rounds, runtime corpus); missing fields are omitted.
- `src/report/emit.ts` — `emitReport` / `emitFinalReport` / `emitNeedsHumanReport` persist via `store.artifacts.put` and append `report.generated` with the artifact ref; no user-tree mutation.
- Production emission: `createConvergenceDriver` emits final report on `DONE` and NEEDS_HUMAN report on convergence/rollback terminals; council drivers and exhausted comparison (`handleNoComparisonWinner`) emit NEEDS_HUMAN reports via shared `emitNeedsHumanReport`.
