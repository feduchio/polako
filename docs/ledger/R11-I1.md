# R11 I1 — worker loop bounds

**Date:** 2026-09-25. **Base:** `765523d`.

What landed:

- `list` skips `node_modules`, `.git`, `dist`, `.polish`, including a request that names one of those directories.
- `search` passes `--glob !node_modules` and `--glob !.git`. `--glob` is now an allowed ripgrep option.
- `read` with no range returns at most 400 lines.
- A tool result over `toolResultTokenCap` (maxTaskTokens/8, clamped to 500–4,000 tokens) is stored whole in CAS and the model sees a summary. `run_command` output above 400 tokens goes through `compressOutput` first.
- The digest of `search`, `list`, and `read` carries the result (`0 matches`, `N entries`, a line range) and a repeat count.
- The third identical `(tool, arguments, result)` with an unchanged diff ends the loop as `STALLED` and emits `worker.loop_stalled`. No model call decides it. `read`, `write`, and `apply_patch` are not in this check: three reads of one file are the progress tracker's case, scored at turns 8 and 12.
- `providers_unavailable` is kept for a provider refusal (and for review, which was never the false label). A candidate that simply never finished is `no_candidate_finished`. The review-path tests that expect `providers_unavailable` were left alone: they describe reviewers that are actually unavailable.
