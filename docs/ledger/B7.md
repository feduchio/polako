# B7 — Supervisor council v1

**Status:** CONTRACT LOCKED  
**Class default:** PHASE_REQUIRED  
**Plan:** Fable §17 B7; §1 immutable mission; three task origins; §10 context construction.  
**Prompt:** Planner, Scope Guardian, Judge; real mission interpretation and decomposition.

## Required behavior

1. After baseline exists, council produces a versioned `MissionInterpretation` (goals, requirements `R\d+`, constraints, non-goals, success, ambiguities). Raw `Mission` is never mutated.
2. Blocking ambiguity → `NEEDS_HUMAN` before EXECUTING.
3. Planner decomposes interpretation into a Task DAG. At least one coding task when the mission requires a code change. Tasks use `createTaskFromRequirement` with `baseCheckpointHash` = current checkpoint (baseline checkpoint after baselining).
4. Scope Guardian rejects tasks that expand past interpretation/non-goals. Out-of-scope task is not enqueued as coding work.
5. Judge resolves council disagreements deterministically from recorded votes; provenance in `supervisor.decision` events.
6. Production phases:
   - `INTERPRETING_MISSION` — real interpretation persisted (`mission.interpreted`, `interpretationId` on run).
   - `PLANNING` — real task creation, not a stub advance to EXECUTING.
7. Model selection (`DISCOVERING_MODELS`) is a distinct phase: broker catalog/probe records available models. Council does not hardcode model names.

## Prohibited shortcuts

- Hardcoded interpretation that ignores mission text (except in tests that still go through the council API with a scripted provider).
- Planner emitting 0 coding tasks for an explicit fix-the-bug mission.
- Creating coding tasks from UNCERTAIN findings (B5).
- Stub INTERPRETING_MISSION / PLANNING in production composition.

## Deterministic evidence

- Scripted council: bugfix mission → interpretation with ≥1 requirement → ≥1 coding task with origin `mission_requirement`.
- Blocking ambiguity → NEEDS_HUMAN, no coding tasks dispatched.
- Scope Guardian drops a task whose statement contradicts non-goals.
- Mission hash unchanged after interpretation.
- Production driver test: INTERPRETING_MISSION writes interpretation; PLANNING writes tasks.
- `pnpm check`.

## Global invariants

Immutable mission; interpretation versioning; closed task origins; instruction hierarchy (council prompts obey A11 boundary).
