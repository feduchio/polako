# R0 — Lift the cost restriction and put a budget under it

**Plan:** `docs/RECOVERY.md` §3 R0. **Base:** `e594bbc` (the plan commit; documentation-only above
HOST `e87dd26`).
**Class:** operator configuration. Production code changes: none expected.
**Reviewer lane:** GPT (`gpt-5.6-sol-high`), one lane, per user instruction 2026-09-15.

## Authority

`docs/RECOVERY.md` §2: the OpenRouter key is funded to $5 and paid models are permitted. §1.2:
94.8% of 2,600 review executions never reached a model because the free tier caps the **account**
at 20 requests/minute. R0 removes the cause; R1 removes the механизм that mistook it for a model
property.

## Defect (normative)

1. `routing.costEligibility = "free_only"` in `~/.polish/polish.toml:30-31` confines routing to
   free models, which is the population subject to the account-wide 20 rpm cap.
2. `budget.maxRunUsd` is `null` (`src/domain/config.ts:125`) and no config sets it. On a free key
   that is harmless; with (1) lifted it means a run may spend the whole key.

(1) must not be changed without (2), in the same change.

## Required end state

- `[routing] costEligibility = "ceiling"` with both `maxInputCostPerM` and `maxOutputCostPerM`
  set to finite, non-zero values chosen from observed OpenRouter pricing, not from memory.
- `[budget] maxRunUsd` set to a finite value that bounds a single run.
- Ceiling values justified by: the price distribution at the time of the change, and the
  token volume of the largest run in the store.

## Acceptance checks

Both are empirical and run against the live daemon; neither is a unit test.

1. **A paid model is actually selected.** After the change, a `polish run` produces at least one
   `model.call` event whose model is not a `:free` route and whose `usage.costUsd > 0`.
   Evidence: the event row, quoted, with the query that produced it.
2. **A run that hits `maxRunUsd` is rejected with a named reason.** A run launched with a
   `--budget-usd` small enough to bind terminates without reaching `DONE`, and `polish status`
   reports a reason that names the budget — not `terminalReason: null`, and not a reason that
   attributes the stop to the model.

Check 2 is the one that can fail: `docs/RECOVERY.md` R3 records that the FAILED path does not
always build a reason. If it fails, the repair belongs to R3 and is **not** forced into R0 — but
R0 does not become acceptable by delegating it. **R0 stays open until check 2 passes.** R3's
acceptance must therefore re-run check 2 against this contract, and only then is R0 closed.

*(Amended after review round 1, which rejected the original wording — "the observation is recorded
and the repair belongs to R3" — as waiving an acceptance criterion rather than meeting it. The
reviewer was right: an item whose own check is unmet is not accepted, whoever fixes it.)*

## Non-goals

- Changing the 429 handling (R1), the canary (R2), the terminal reason construction (R3).
- Raising `budget.maxRunUsd`'s **default** in `src/domain/config.ts`. The default protects a free
  key that does not need protecting; the funded key is this operator's, and operator settings live
  in `polish.toml`. If review shows the default is the right site, that is a code change and R0 is
  reformulated rather than widened.
- Any model pin. Supervisor pins in `polish.toml` stay as they are.
