## What the item fixed

Three folds that lost data, one per file.

- **`usdUsage`** summed priced calls and returned a bare number, so a partially priced run showed the
  operator a lower bound as a total. It now returns `{ usd, unpricedCalls }` and `render.ts` shows the
  count. Returning it without rendering it would have left the operator reading the same number.
- **`foldModelCallUsage`** dropped `taskId: null` calls from `perTask`, so reviewers and the council —
  78.7% + 4.1% of all spend by finding 29 — were attributable to no dimension. Untasked tokens now go
  to `perRole`, in its own field, because `exhaustedDimensions` enforces every `perTask` key as a task
  budget.
- **`collectEntries`** demoted an older failing command with `text.replace(/: [\s\S]*$/, "")`, which
  matches from the **first** `: `, so `git commit -m "fix: x" -> exit 1` demoted to
  `git commit -m "fix`. `DigestEntry` now carries the tail as a field and demotion sets it to `null`.

## The finding that matters: the accumulators lost the keys they were most exposed to

Round 1's GPT lane wrote `role: "__proto__"` into the fold. `perRole["__proto__"] = 5` on an object
literal **sets the prototype** rather than creating an own key, so the tokens vanished;
`perRole["constructor"] ?? 0` read back `Object` and the accumulator became a string. Both keys arrive
from an event payload, so neither was unreachable by construction. Fixed with `Map`s converted once
by `Object.fromEntries` — applied to `perTask` as well, which is not scope creep: MC5 sums `perTask`
and is false without it.

**Grok passed round 1 having attacked the same invariant with ten hand-chosen inputs** — duplicate
call ids, conflicting duplicates, malformed usage, empty-string ids, zero-token calls — and finding it
held every time. The gap was not effort. It was that a hand-written attack contains only the shapes
its author thought of, and neither lane's author thought of a prototype key.

That is why the fix added **AC6b**, a `fast-check` property over generated task ids and roles drawing
explicitly from `__proto__`, `constructor`, `toString`, `hasOwnProperty` and the empty string. It
kills the object-literal mutant in one run and shrinks to a single call. In round 3 Grok pushed the
generated set further by hand — `valueOf`, `__defineGetter__`, numeric-looking keys, a 10k-character
key, emoji, a lone surrogate, twenty in all — and every one landed as an own property with the right
count.

**The transferable rule:** when a fold's keys come from a payload, the key space is adversarial input
even when no adversary exists, and a fixture cannot cover it. That is the case for a property check.

## MC5 was false as written, twice, in two different ways

Revision 1 said *"for any event set, `sum(perTask) + sum(perRole) === runTokens`."*

1. **Keys.** Falsified by `__proto__`, above. Repairable, and repaired.
2. **Arithmetic.** Falsified by `inputTokens: 1e16` plus two one-token calls: `1e16 + 1 + 1` rounds to
   `1e16` while `1e16 + 2` does not. **Not repairable at this seam** — it is a property of IEEE-754
   addition that any two-grouping sum has, including the code at base, and the only escape is exact
   arithmetic. MC5 now states its domain: non-negative integer counts whose running total stays inside
   `Number.MAX_SAFE_INTEGER`.

Revision 2 justified the domain by saying it "contains every input a provider can produce". Round 2
checked and that was too strong: `maxRunTokens` defaults to `null` with no upper bound
(`src/domain/config.ts:126`) and `OpenAICompatProvider` takes `parsed.usage?.prompt_tokens ?? 0`
without a safe-integer check (`src/providers/openaiCompat.ts:94-97`). Revision 3 states the narrower
claim that survives: exact inside the domain, and outside it no grouping-independent sum exists
without exact arithmetic, so bounding token counts belongs where they enter the system, not in a fold.

## One clause deleted, and why that is the second time

Round 2's only finding was class (c): MC8 required the digest's **sort tie-break** to use the composed
`text + tail`, and that cannot be observed. The comparator's earlier arms are `priority` then `seq`,
`seq` is unique per entry, so the lexical arm is unreachable through `buildLoopDigest` whatever string
it compares; swapping it passes all 916 checks.

Both lanes reached this independently — Grok recorded it as a note in round 1, GPT as a finding in
round 2 — and both said the same thing about the remedy. GPT's words: *"Delete that subclause rather
than adding a source grep or artificial unreachable check."* That is the addendum recorded with P1.10
being applied by the reviewers rather than to them. The clause went; the code keeps the composed form
because consistency costs nothing.

### What the fix finally was, and why the earlier ones were not enough

Rounds 1–3 widened a single aggregate fixture and each time three more survivors appeared. The cause
turned out to be **the aggregate, not its contents**:

- Reusing the neighbouring fold's `unknownCostCalls` produced the right number because deduplicating
  one repeated call (−1) and misclassifying one negative price (+1) **cancelled**.
- A `usd` **sum** cannot observe a priced **zero** at all — zero contributes nothing, so deleting that
  call entirely left the assertion green.

AC1 is now driven **one shape at a time**: one single-event fixture per unpriced shape, per finite
price, and per usage-less shape, plus one two-event fixture for a repeated `callId` and one for
`model.call_started`. A single-call fixture has nothing to cancel against, and a lone zero-priced call
must yield `usd === 0` rather than `null`.

### Why the Grok lane passed it, in its own words

Asked to examine its own miss rather than re-run the same sweep, it was precise, and this is the most
useful paragraph in the file:

> *"I ran that list, confirmed the code matched the clause, and moved on. I did not write a wrong
> classifier that still yields `1`. … What I would have had to do differently: treat a two-sided
> membership clause as unobserved until each boundary has an input on both sides, one shape at a time.
> Equal counts across two classes make the classes interchangeable; an aggregate `toBe(1)` observes a
> number, not a predicate."*

It then checked all eight against its own original method and confirmed **none** of them would have
died: the fixture had no zero, no negative, no duplicate id, no non-`model.call` event, and its only
unpriced price *was* `null`.

The difference is not diligence. It is that verifying *the code matches the clause* is not the same
as verifying *a wrong implementation would fail a check*, and only the second is what a reviewer adds.

### Both lanes called the stop

The fourth round was the fourth on one clause of a check whose production code was correct, which is
the shape `docs/ledger/PHASE-C.md`'s stopping rule exists to catch. Both lanes were asked directly and
both said stop:

- GPT: *"Yes. Further widening of MC2 has become a treadmill and should stop. Remaining survivors
  require conditions unrelated to MC2's predicate."* Its exhibit was a mutant conditioned on
  `inputTokens === 4`.
- Grok: *"Agree."* Its exhibit was special-casing `costUsd === Number.NEGATIVE_INFINITY`, which
  `Number.isFinite` already covers — *"a fixture-list leftover, not a plausible implementation of 'not
  a finite number'. Adding `-Infinity` would be the next treadmill step."*

Recorded because the rule is easier to state than to apply, and two independent lanes agreeing on
where the line falls is the best evidence available that it was drawn in the right place.
