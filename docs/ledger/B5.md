**Prompt:** dedupe; reproduction/evidence; VALID/REJECTED/UNCERTAIN; only VALID blocking finding creates a coding task.

## Required behavior

1. Raw findings are fingerprinted and deduped (existing `findingFingerprint`). Duplicates become `DUPLICATE`, not new work.
2. Triage: opinions without evidence → `NOTED`. Blocking claims with evidence enter `VALIDATING`.
3. Validation produces `FindingValidation` with method, verdict, rationale, evidence artifacts. VALID requires evidence refs (existing strict schema).
4. Reproduction may be a failing test **or** a `RuntimeScenario` (B12). Successful reproduction of a defect ⇒ VALID; failure to reproduce with adequate attempt ⇒ REJECTED or UNCERTAIN with recorded reason.
5. Only `VALID` + `blocking=true` creates a coding `Task` via `createTaskFromValidFinding`. UNCERTAIN may create an investigation task (`touchesProductCode=false`). REJECTED creates nothing.
6. VALID reproduction artifacts (test or runtime scenario) are added to the Mission Acceptance Corpus for the mission.
7. Production `VALIDATING` driver performs this and may return to `PLANNING` when a coding task is created.

## Prohibited shortcuts

- Supervisor converting UNCERTAIN/REJECTED into a coding task.
- VALID without evidence artifacts.
- Auto-fixing reviewer speculation.
- Skipping corpus registration for a validated reproduction scenario.

## Deterministic evidence

- Duplicate fingerprint → DUPLICATE, one surviving finding.
- VALID + blocking → task origin `valid_finding`.
- UNCERTAIN → investigation task only; coding factory throws.
- REJECTED → zero tasks.
- VALID without evidenceRefs rejected by schema/factory.
- Corpus gains an entry after VALID reproduction.
- `pnpm check`.

## Global invariants

Closed task origins; Mission Acceptance Corpus accumulation; fact/evidence integrity (validation evidence events exist for this run).
