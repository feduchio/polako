# R7 — A worker that cannot finish must stop, not spend

**Origin:** `docs/ledger/R5-run.md` — observed in `run_01m2hfb2mnmvd10384k320`, not reasoned about.
Created under `docs/RECOVERY.md` §4 rule 5. **Status:** contracted, not implemented.
**Reviewer lane:** GPT, one lane.

## Defect (normative)

One task. Five attempts. Two candidates each. **148 worker calls and 492,632 tokens**, and not one
candidate finished:

```
sqlite3 "file:$HOME/.polish/polish.db?mode=ro" \
  "select json_extract(json,'$.payload.candidate.state'),
          json_extract(json,'$.payload.candidate.error'), count(*) from events
     where run_id='run_01m2hfb2mnmvd10384k320' and type='candidate.state_changed' group by 1,2;"
DISCARDED | BUDGET_EXCEEDED | 12
```

`BUDGET_EXCEEDED` here is `AgentRunner`'s per-task token allowance, not the run's USD budget: the
worker loop ran until `totalTokens > maxTokens` and stopped mid-work (`src/agents/runner.ts:100`,
`:116`). Every candidate died that way. The run then failed with no survivor.

That is 35% of every worker token this tool has ever spent, and 96.4% of all recorded dollars are
the worker's (`docs/ledger/R6-run.md`) — so this is not a corner of the cost, it is the cost.

The product ships a detector for this exact shape at the process level —
`detectTestOnlyTreadmill`, and `docs/RECOVERY.md` §1.5 names "no maximum number of reviews" as the
pathology the process had and the product detected. The worker has neither.

## The question this item must answer first

**Why did the worker not finish?** The contract cannot be written past this point without it, and
guessing is what §4 rule 2 forbids. The evidence exists in the store: `model.call` artifacts hold
each request and response, and `worker.started` / turn events hold the loop's shape. Before any
code, read enough of them to say which of these it was:

- The task was too large to finish inside the allowance — a planning defect, not a worker defect.
- The loop repeated itself — the same tool call, the same edit, the same failure, turn after turn.
- The model never emitted `finish` and the loop had no other way to end.
- The context pack grew until each turn cost more than the last.

Each has a different repair, and only one of them is "bound the worker".

## Required end state (provisional, pending the above)

1. A worker that is not converging is stopped by something that names the reason, before its
   allowance is gone. `BUDGET_EXCEEDED` is what running out looks like, not what noticing looks
   like.
2. The stop is visible per candidate, with what the worker had done by then, so the next attempt
   has more than "it ran out" to go on.

## Acceptance checks (provisional)

1. A scripted worker that repeats one turn forever is stopped before consuming its allowance, and
   the candidate's recorded error names the repetition rather than the budget.
2. A worker that finishes normally is unaffected — same calls, same tokens.
3. Re-run R5 against `~/screen-audit-toolkit` with the same mission: the run reaches `REVIEWING`,
   and R5's acceptance becomes evaluable.
