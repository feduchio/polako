## Why

Review is 78.7% of every token this tool has spent, and `review_adversarial` alone is 64.4%
(`docs/ledger/g1-baseline.md`). Axes are dispatched sequentially in `DEFAULT_REVIEW_AXES` order, so
`adversarial` runs last at the default `reviewersPerRound` of 3, and the earlier axes' results for the
round are already persisted when it is reached.

## Mandatory clauses

**MC1 — dispatch site.** The skip decision is made **only** inside the axis loop at
`src/engine/reviewDrivers.ts:170-186` (the `for (const axis of missingAxes(...))` loop). `exhaustedAxes`
and its call site at `src/engine/reviewDrivers.ts:126` and the helper near `:895-915` are **not**
modified. Rationale: that helper counts sticky failures and is not dispatch.

**MC2 — the decision reads persisted state, not the pre-loop snapshot.** `roundExecutions` is bound at
`src/engine/reviewDrivers.ts:121-123` from `allExecutions` read at `:111`, before the loop runs. The
skip decision MUST re-read executions from the store (`ctx.store.repos.reviewExecutions.listByRun`) and
filter to the current `(hash, roundIndex)`. A decision taken against the pre-loop snapshot would see
zero prior findings on every tick and would skip even when `correctness` had just reported a finding in
the same loop iteration sequence.

**MC3 — the predicate.** `adversarial` is skipped for the round when **all** of:
1. `ctx.config.review.skipAdversarialWhenClean` is `true`;
2. the axis about to be dispatched is `"adversarial"`;
3. among the re-read executions for this `(hash, roundIndex)`, the set of **completed** executions
   whose `axis !== "adversarial"` is **non-empty**;
4. every execution in that set has `findings.length === 0`.
Clause 3 is required: an empty set must not be read as "clean".

**MC4 — the skip is persisted as a completed execution.** It is written through the existing
`review.started` / `review.finished` pair via `appendReviewEvent`
(`src/engine/reviewDrivers.ts:1113`), producing a `ReviewExecution` with:
- `completed: true`;
- `findings: []`;
- `error: "no_prior_findings"` (`ReviewExecutionSchema.error` is already optional,
  `src/domain/review.ts:30`);
- `requestedModel` set to the model that would have been selected for the axis, i.e. the reviewer at
  `reviewers[(preferredIndex + 0) % reviewers.length]` with `preferredIndex = Math.max(0, axes.indexOf(axis))`, matching `reviewAxisWithFallback`'s first choice;
- `finishedAt` set from `ctx.clock.now()`.

`completed: true` is mandatory, not cosmetic: `missingAxes` (`:823`) and `isReviewRoundComplete`
(`src/domain/review.ts:55`) count only completed executions, so `completed: false` would leave the axis
missing and requeue it on every tick — an unbounded loop.

**MC5 — no new event type.** `review.axis_skipped` MUST NOT be introduced. `ReviewExecutionSchema` has
no `reason` field, and projections populate `review_executions` only from `review.started` and
`review.finished` (`src/store/projections.ts:234-235`), so a new type would persist an event that never
becomes a row.

**MC6 — no provider call.** A skipped axis MUST NOT produce a `model.call` event. This is the saving.

**MC7 — config field.** `review.skipAdversarialWhenClean: z.boolean().default(false)` added to
`ReviewStrategySchema` (`src/domain/config.ts:39-52`). **Default `false`.** `docs/PLAN.md` §1 forbids
enabling a cost-reducing behaviour by default while the quality gate is not `pass`, and it is not. The
default is flipped in a separate one-line commit when P2.2 reaches `pass`.

**MC8 — no other behaviour changes.** No change to axis order, `reviewersPerRound`, exhaustion
counting, rate-limit handling, ensemble override, or the checkout/artifact path.

**MC8a — added in revision 4, from review round 1.** A skipped execution completed **without reaching
a provider**, so it is not evidence that its model works and MUST NOT lift a sticky exclusion.
`recentlyRateLimitedReviewModels` (`src/engine/reviewDrivers.ts:734`) rehabilitates a model as soon as
any completed execution for the checkpoint names it, and the skip row is completed, so at base a model
that returned 429 was un-excluded by a row that never reached it and the next round called it again.
Three production call sites consume this (`src/daemon/composition.ts:394`, `:558`, `:610`).

**MC8b — added in revision 4, from review round 1.** The skip row's `requestedModel` must be the model
`reviewAxisWithFallback` would actually have reached — its first choice at `preferredIndex`, then the
ring, **passing over models already rate-limited in this pass**. When every model is excluded there is
nothing to attribute a skip to and the normal path must run instead. Revision 3 named the preferred
model unconditionally, which was wrong whenever that model had already failed in the same pass.

## Acceptance criteria

Each AC is one test. The contract is finite; these are all of it.

**AC1 — also the discriminating test for MC2.** With the flag `true`, a round in which `correctness`
and `regression` both complete with `findings: []` issues **two** provider calls, not three, and the
round is complete with **three** executions, of which exactly one has `axis: "adversarial"`,
`completed: true`, `findings: []` and `error: "no_prior_findings"`. An implementation that reads the
pre-loop `roundExecutions` snapshot fails this, because that snapshot is empty on the first tick and an
empty set is not clean under MC3 clause 3, so it would issue three calls.

**AC2** With the flag `true`, a round in which `correctness` completes with **one** finding issues
**three** provider calls, and no execution carries `error: "no_prior_findings"`.

**AC3** With the flag `false` (the default), a round in which both earlier axes return `findings: []`
issues **three** provider calls. Asserted against the schema default, not against a literal.

**AC4** After a skipped round, the next driver tick does **not** requeue `adversarial`: the round is
reported complete and the phase advances to `VALIDATING`.

**AC5** *Withdrawn in revision 2 as vacuous — see the header. MC2 is discriminated by AC1.*

**AC6** No provider call is recorded for the skipped axis in the skipped round (MC6), asserted on the
`ScriptedProvider.calls` log, which is the observable stand-in for a `model.call` event in the driver
tests.

**AC7** A static check asserts the string `review.axis_skipped` appears in no non-test file under
`src/` (MC5).

**AC8 — added in revision 3, closing a clause no check observed.** MC3 clause 3 (an empty set of
completed other axes is not "clean") is **unreachable in the default axis order**, because `adversarial`
runs last and is only reached once the earlier axes have completed. A mutation removing the guard
therefore passed every test in revision 2 — a class-(c) gap, the kind reviewers are explicitly asked to
name. The clause is kept rather than deleted, because `[].every()` is `true`, so without it a change to
axis order or `reviewersPerRound` would silently skip on no evidence. It is made observable through the
driver's existing `resolveAxes` option, dispatching `adversarial` first: three provider calls are
issued and no execution carries `error: "no_prior_findings"`. No symbol is exported for the test.

## Out of scope

Flipping the default to `true`. Any change to the other two axes. Any change to
`reviewersPerRound`. The falsifier redesign, which is `docs/PLAN.md` P3.2 and void if P3.1 drops this
axis first.

## Blocking definition for this task

Per `docs/PLAN.md` §9: a finding blocks only if it names a user-visible behaviour change or an
invariant violation, with a reproduction. Test-strength observations are notes and do not reopen a
round. A survivable mutant that must branch on state unrelated to what it changes is a note.

## Acceptance criteria added in revision 4

All six exist because review round 1 named them. Each was mutation-verified to fail a named assertion.

**AC9** With two reviewers where the first returns 429 on `correctness` and the second completes both
earlier axes, the skip row's `requestedModel` is the **second** model — the one that would actually
have been called (MC8b). Kills the mutation that names the preferred model unconditionally.

**AC10** With three reviewers, the adversarial slot's `preferredIndex` resolves to the **third** model,
and no provider call is made to it. Kills the `reviewers[0]` simplification, which round 1 demonstrated
survives the revision-3 suite.

**AC11** `correctness` clean and `regression` reporting a finding → no skip, three provider calls. Kills
the "look only at `correctness`" simplification. Round 1 noted no check had the later earlier-axis dirty.

**AC12** An **incomplete** other-axis execution is not "clean": seeded directly, because the default
axis order cannot reach `adversarial` with an incomplete earlier axis. Kills the mutation that drops
MC3's `completed` qualifier.

**AC13** The skip emits both `review.started` and `review.finished` (MC4's required pair, since
projections build rows from both).

**AC14** The rehabilitation guard (MC8a). A completed skip row naming a model, followed by an
incomplete 429 for the same model in a later round, leaves that model **excluded**.

Note on why AC9 alone was insufficient, recorded because it is the same trap as revision 2's AC5: with
MC8b in place the skip never names a rate-limited model *within one pass*, so AC9 cannot observe the
rehabilitation guard at all — removing the guard leaves AC9 green. The guard is cross-tick, because
the `rateLimited` set is per-tick. AC14 constructs that sequence directly. Found by mutation, not by
reading.

## Acceptance criteria added in revision 5, after review round 2

Both lanes returned `FAIL` on the same defect, found independently: revision 4's repair was
incomplete. `recentlyRateLimitedReviewModels` has **two** rehabilitation paths and revision 4 guarded
one.

**The defect.** The `latest` map (`src/engine/reviewDrivers.ts:737-748`) keeps the newest row per
model. The exclusion loop begins `if (execution.completed || execution.error === undefined) continue`,
so when the latest row is a completed skip the earlier 429 is never examined and `completedKeys` is
never consulted. Guarding only `completedKeys` therefore closed the order *skip then 429* and left
*429 then skip* open — and the second is the reachable one, because the `rateLimited` set is per-tick:
a model that failed in an earlier round can be the preferred model for a later round's skip. AC14
tested only the order the revision-4 guard could save.

**Repair.** A skip row is evidence in neither direction, so it is excluded from `latest` as well.

**AC15** A 429 for a model followed by a **later** skip row naming it leaves that model excluded.
Mutation-verified: restoring the old `latest` filter fails this and leaves AC14 green.

**AC16** A clean verdict from a **different round** does not justify a skip. Round 2's GPT lane found
that dropping the checkpoint/round scope from `adversarialSkipApplies` passed all 873 tests. Recorded
as a note there; closed here because the scope is load-bearing for MC2 and MC3.

Both were mutation-verified against the exact mutants the reviewers described.
