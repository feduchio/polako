## How the joins are made, so a second implementer gets the same numbers

One population decides everything, and nothing is classified by its own timestamp.

1. An **execution** is bucketed by the `ts` of the `review.finished` event that recorded it (MC1).
2. A **finding** inherits its execution's bucket, joined exactly: `raiseFinding` appends
   `finding.raised` with `causedBy` set to the review execution's id
   (`src/engine/reviewDrivers.ts:866-867`, `:1240-1251`), which lands in `event_causes`. A finding
   raised after the cut-off from a pre-cut-off execution was still parsed by the broken parser, so
   it is ineligible.
3. **Validations and tasks** follow their finding.
4. A **reviewer `model.call`** is attributed by `docs/PLAN.md` §1's rule — scan `events` in
   `(run_id, seq)` order and attribute the call to the execution opened by the most recent preceding
   `review.started` for that `(runId, axis)` — and then inherits that execution's bucket. A call
   issued before the cut-off for an eligible execution is still that execution's call.
5. **Triage survival** is status outside `RAW`, `DUPLICATE`, `NOTED`, or the existence of a
   validation row, which is written only for triage disposition `validate`
   (`src/findings/validator.ts:95-98`). `RAW` means triage has not run, so `RAW` is not a survivor.
6. Anything that cannot be joined is `unattributed` and reported as such. It is never eligible.

## What would make P2.1 decidable

Not a different query. A run that reaches `REVIEWING` on the current tree with a working provider
lane, so that a reviewer response is parsed by the fixed parser and a finding row exists. Recorded
here as the blocking condition, not scheduled as new scope.

## Review

**GPT round 1 on `e7dba19` — seven findings, all accepted.** Four were defects in the
classification, found by building synthetic stores rather than by reading: eligibility fell back to
`review.started` and admitted an execution that never finished; findings, validations and reviewer
tokens were each classified by their own timestamp instead of their execution's, which leaked a
late-raised finding into the eligible population and pushed an eligible execution's early call into
the ineligible one; a `RAW` finding counted as having survived triage; and the verdict summed a
fixed three axes while `ReviewAxisSchema` admits eight, so an eligible finding on a fourth axis
appeared in the table but not in the verdict. The remaining three were in the report: the eligible
zero table sat beside the MC3 verdict against AC2, the record carried literal `10|`-style
line-number prefixes that broke its Markdown, and the provider-failure claim was stronger than the
distribution supports.

The fixes are the joins listed above, the `--selfcheck` mode with its mutation table, AC2
suppression of the empty table, and the corrected failure distribution. The round cost nothing in
production code because there is none.
