## MISSION_CRITICAL invariants

1. **UNCERTAIN-only entry.** Debate may start only for a finding whose current status is `UNCERTAIN` after a persisted B5 evidence validation left it uncertain at the current run checkpoint. No other status enters debate. Re-entry for the same `(findingId, finding.checkpointHash)` after a terminal debate outcome is forbidden.
2. **Evidence-bound roles.** Prosecutor, Defender, and Judge receive only persisted finding fields, prior `FindingValidation` records, and artifact refs already in the Store / acceptance corpus for that run. They must not invent file paths, command output, or reproduction steps. Free-text persuasion cannot create evidence refs.
3. **Structured judge only.** Judge emits machine-parsed `{VALID|REJECTED|UNCERTAIN}` plus non-empty rationale. Malformed / empty / non-JSON judgment → hard failure: no `VALID`, run-phase `NEEDS_HUMAN` when investigation is already B6-exhausted, else residual `UNCERTAIN` eligible for investigation per the total order.
4. **Persist before terminal effect.** Named Store events (added to `KNOWN_EVENT_TYPES`) record, in order:
   - `finding.debate_started` (finding id, checkpoint hash, role `ModelRef`s, causal B5 validation id) while status remains `UNCERTAIN`;
   - per-round role artifacts (`prosecutor` / `defender` / `judge`) with round index;
   - `finding.debate_outcome` (terminal verdict, rationale, round count, causal refs);
   - then, in one apply batch that no intervening `CONVERGENCE_CHECK` tick can observe mid-way: `UNCERTAIN → VALIDATING → {VALID|REJECTED|UNCERTAIN}` via `assertTransition(FINDING_TABLE)`, `finding.validated` with `method: "finding_debate"`, terminal `finding.status_changed`, then `task.created` if any.
   Mid-debate crash (started, no outcome): status is still `UNCERTAIN`; resume completes missing roles from already-persisted arguments without re-rolling completed roles; never start a second debate for the same key. Outcome persisted without status/task effect: apply that outcome once.
5. **DONE visibility.** While debate is open (started, no terminal outcome), the finding **remains** `status === "UNCERTAIN"` for every B6/C2 DONE predicate (`investigationExhausted`, open blocking VALID count, clean-round eligibility). C4 must not leave a stranded `VALIDATING` finding that would hide exhaustion or blocking work from `CONVERGENCE_CHECK`.
6. **Pre-debate evidence for VALID.** Debate `VALID` is legal only when `evidenceRefs` include at least one **pre-debate** Store/corpus artifact already attached to the finding or a prior `FindingValidation` for that finding. Newly persisted debate arguments, verdict JSON, and rationales are provenance only and are **not** sufficient for `VALID`. Judge `VALID` without such a pre-debate ref is a hard failure → no coding task; residual `UNCERTAIN` / `NEEDS_HUMAN` per total order.
7. **Task-origin integrity.** Debate `VALID` may create a coding task only through `createTaskFromValidFinding` for `VALID` + `blocking=true` with `FindingValidationStrictSchema` and invariant 6. Debate must not authorize product-code work from `UNCERTAIN` / `REJECTED` / non-blocking findings.
8. **Three distinct models or skip.** Prosecutor, Defender, and Judge MUST be three distinct cost-eligible `ModelRef`s. If fewer than three distinct eligible models exist (including empty catalog), do **not** run debate, do **not** apply `REJECTED` or `VALID` from a skip, and do **not** assign the same model to Judge and either advocate. Finding stays `UNCERTAIN`; continue with investigation / `NEEDS_HUMAN` in the total order. Same-model Judge is forbidden (self-oracle class).
9. **Method name.** Every debate `FindingValidation.method` MUST be `finding_debate`. Do not reuse `adversarial_verification` as the debate method. Prior B5 UNCERTAIN validation remains in the prefix unchanged.
10. **Corpus honesty.** Debate `VALID` (blocking and non-blocking) registers a Mission Acceptance Corpus entry **after** the debate `finding.validated` event exists, deferred like B5. Kind MUST be an existing `CorpusEntryKind` derived from the cited **pre-debate** evidence / prior validation method (e.g. prior `failing_test` → `regression_test`; prior runtime → `runtime_scenario` / `runtime_evidence`). Do not invent a failing test. Do not file `runtime_scenario` / `regression_test` when the only artifacts are debate transcripts. If invariant 6 holds, a legal `VALID` always has a real kind to derive.
11. **Investigation-round coherence.** When C4 spawns a B5 investigation after residual `UNCERTAIN`, it MUST persist an updated `finding.investigationRounds` (or the exact Store fact B6/`CONVERGENCE_CHECK` already reads) so C4 and convergence cannot diverge. This is coherence with accepted B6/C2, not a license to close other B findings.
12. **Cost / secrets / no C3 oracle.** Debate roles use Polish broker routing and `routing.costEligibility`. Acceptance uses scripted/injected providers only — no live/paid calls. No secrets in the repo. C3 sidecar must not be wrapped as a debate provider.

## Production path and total order

Inside production `createValidatingDriver`, for each finding that just received a persisted B5 `UNCERTAIN` validation at the current checkpoint, **before** any investigation `task.created`:

1. Persist B5 UNCERTAIN validation + status (existing B5). `FindingValidator.validate` stays RAW-only.
2. If a terminal debate outcome already exists for `(findingId, finding.checkpointHash)`, do not debate again; apply any unexecuted outcome effect once.
3. Else if three distinct cost-eligible debate models resolve:
   - append `finding.debate_started` (status stays `UNCERTAIN`);
   - run at most `maxDebateRounds` evidence-bound rounds; persist each role artifact;
   - on terminal `VALID`/`REJECTED` from Judge, or after `maxDebateRounds` still `UNCERTAIN`, or hard failure (malformed/empty/throw): append `finding.debate_outcome`;
   - apply the terminal batch from invariant 4.
4. If fewer than three distinct eligible models: skip debate (invariant 8); finding remains `UNCERTAIN`.
5. After debate apply or skip:
   - debate `VALID` + blocking → `createTaskFromValidFinding` + corpus (invariants 6, 7, 10);
   - debate `VALID` + non-blocking → corpus only, no coding task;
   - debate `REJECTED` → no task;
   - residual `UNCERTAIN` (skip, all-uncertain rounds, or hard failure that did not escalate the run):  
     - if `investigationRounds < maxInvestigationRoundsPerFinding`, spawn B5 investigation and persist the incremented round count (invariant 11), then continue toward `PLANNING` as today;  
     - else run-phase `NEEDS_HUMAN` (same exhaustion predicate B6/`CONVERGENCE_CHECK` uses). Hard failure when already exhausted also → `NEEDS_HUMAN`.
6. C4 does not change B6 DONE authority, C2 pathology ordering, or C3 comparing. A blocking finding with `investigationRounds >= max` that enters debate cannot produce `CONVERGENCE_CHECK` → `DONE` at any point during an open debate.

## Role protocols

- **Prosecutor:** argue valid using only supplied evidence/reproduction.
- **Defender:** challenge weak/non-reproducible claims; prefer `REJECTED` / residual `UNCERTAIN` over false `VALID`.
- **Judge:** decide from arguments plus persisted evidence only; structured verdict JSON.

Protocol text under `protocols/` cannot weaken TaskOrigin or evidence requirements. Actor provenance: extend `ActorKind` for prosecutor/judge as needed, or use existing kinds with an explicit `role` field — but every debate validation/event must record which role spoke.

## Deterministic acceptance checks

1. Non-`UNCERTAIN` finding refused; no provider calls.
2. Scripted `VALID` with pre-debate evidence: legal transitions; blocking → one `valid_finding` coding task; non-empty pre-debate `evidenceRefs`; debate events before task; corpus kind derived from pre-debate evidence.
3. Scripted `VALID` without pre-debate evidence artifacts → no `VALID` upgrade, no coding task (fail closed).
4. Scripted `REJECTED` → `REJECTED`, zero tasks.
5. Scripted all-`UNCERTAIN` for `maxDebateRounds` with investigation rounds remaining → investigation spawned and `investigationRounds` incremented; no coding task.
6. Same with investigation already exhausted → run-phase `NEEDS_HUMAN`; no coding task; no DONE.
7. Malformed judge / empty advocate / throw → no `VALID`; exhausted → `NEEDS_HUMAN`.
8. Fewer than three distinct eligible models → no debate calls that invent a verdict; residual `UNCERTAIN` follows step 5.
9. Crash after `debate_started` before outcome: resume completes once; status never stranded as `VALIDATING`; DONE predicates still see `UNCERTAIN` while open.
10. Crash after outcome before effect: one status/task effect; no second debate for the same key.
11. Replay of the same Store prefix reuses persisted outcomes; does not re-call providers.
12. B5 `UNCERTAIN` + debate enabled does not persist investigation `task.created` before the debate terminal outcome.
13. Blocking finding at investigation exhaustion entered into open debate cannot yield `CONVERGENCE_CHECK` DONE.
14. Existing B5, B6, C2, C3, control-plane, and broker tests remain green.
15. `pnpm check` and `pnpm build` on Node 24.20.0 with no live/paid provider call.
