## Required behavior

1. `hasConverged` counts only clean rounds whose `checkpointHash` equals the current run checkpoint. Any new checkpoint invalidates prior rounds for counting.
2. Recording a clean round requires proof-of-review:
   - requested reviewer ids
   - completed reviewer ids (all required completed)
   - each: provider/model, axis, artifact/checkpoint reviewed (must equal current hash)
   - structured results
   - validated blocking findings = 0
3. `rawFindings = 0` without those review execution records is **rejected** by the recording API / domain function. A5 stub tests may still inject events only inside stub-harness tests; production recording path cannot.
4. Anti-fake-DONE: `assertCodeChangeMissionMayComplete` (name flexible) returns FAIL for change-required missions when any of: 0 coding tasks, 0 worker executions, 0 candidate worktrees, 0 candidate commits, 0 successful independent gates, 0 integrated code changes, final checkpoint == baseline, 0 actual review executions, clean rounds without proof. DONE transition in production must call this.
5. Dominance: checkpoint evidence vectors use existing `dominates`. Rollback creates a rollback checkpoint on the integration lane; does not stash/reset the user tree.
6. Production `CONVERGENCE_CHECK` driver: if anti-fake-DONE fails → `FAILED` or `NEEDS_HUMAN`, never DONE; if required clean rounds not met → `REVIEWING`; if runtime required and evidence missing/stale/failed → cannot DONE (B12); else DONE.
7. Change-required vs review-only missions: interpretation/task graph tells whether coding was required (mission requirements with coding tasks or `touchesProductCode`). Review-only missions may DONE without a code diff; change-required must not.

## Prohibited shortcuts

- Administrative clean rounds.
- DONE because stub `STUB_NEXT` says so.
- Counting clean rounds from a previous checkpoint.
- Relabeling anti-fake-DONE as optional.

## Deterministic evidence

- Record clean round without review executions → throw / reject.
- Review executions for hash H cannot clean-round hash H'.
- Required reviewers incomplete → reject.
- Validated blocking > 0 → not a clean round.
- Change-required fixture with empty diff → DONE impossible.
- Change-required with zero workers/candidates/gates/reviews → DONE impossible.
- After new checkpoint, previous clean rounds do not satisfy `hasConverged`.
- Dominance/rollback unit tests on evidence vectors + integration-lane rollback.
- `pnpm check`.

## Global invariants

Clean rounds belong to checkpoint hash; CODE_CHANGING_PHASES; pause/stop still orthogonal; apply is separate from DONE.
