## Three defects, in three files

### A. `usdUsage` omits unpriced calls silently (`src/observe/project.ts:468-481`)

```
function usdUsage(events): number | null {
  ... if (cost !== null) { any = true; usd += cost; } ...
  return any ? usd : null;
}
```

It returns `null` only when **no** call was priced. A run where *some* calls are priced and some are
not returns a number that is a **lower bound presented as a total**. The operator reads
`USD  0.0312` (`src/observe/render.ts:43`) with nothing saying it is partial.

`docs/PLAN.md` §8 already corrects revision 4's claim that this function "returns 0"; it does not.
The defect is the silent omission, not a wrong zero.

### B. `foldModelCallUsage` drops untasked spend from its per-dimension view (`src/convergence/pathology/budget.ts:79`)

```
if (row.taskId !== null) perTask[row.taskId] = (perTask[row.taskId] ?? 0) + row.tokens;
```

`runTokens` at `:76` is correct and counts every call. `unknownCostCalls` at `:77-78` is correct. The
loss is confined to `perTask`: a call with `taskId: null` contributes to the total and to **no**
dimension, so it cannot be attributed. Over the six real runs that is the council, the probes, the
supervisors **and the reviewers** — `src/council/roles.ts:28-33` and `src/review/swarm.ts:86` both omit
`taskId` — which by finding 29 is 78.7% + 4.1% of all spend. The largest cost centre in the system is
the one `perTask` cannot see.

### C. The demotion regex eats the exit code (`src/agents/loopWindow.ts:163`)

```
text: entry.text.replace(/: [\s\S]*$/, "")
```

A failed command's `text` is built at `:142-143` as `` `${argv} -> exit ${code}: ${tail}` ``. The
regex is meant to drop the tail, but `[\s\S]*$` is anchored at the end while the match starts at the
**first** `: ` in the whole string. An argv containing `: ` therefore loses the exit code too:
`git commit -m "fix: x" -> exit 1: <output>` demotes to `git commit -m "fix`. The digest then records
that the command ran and not that it failed — the exact fact the worker needs.

Only the newest failure escapes, because only older ones are demoted.

## Mandatory clauses

**MC1 — `usdUsage` reports what it omitted, and the operator sees it.** It returns
`{ usd: number | null; unpricedCalls: number }`. `src/observe/types.ts:73-77`'s `resources` gains
`unpricedCalls: number`, and `src/observe/render.ts` **renders it** when it is non-zero. Returning the
count without surfacing it would leave the operator reading the same misleading number; the defect is
what the operator is told, not what the function returns.

**MC2 — "unpriced" means priced-call-shaped and unpriced, not failed.** A `model.call` counts toward
`unpricedCalls` when its `usage` object is present and its `costUsd` is not a finite number. A call
with **no** `usage` at all — the 83 null-usage calls behind finding 37's 429 storm — is **not**
counted: it consumed nothing, so calling it "unpriced spend" would overstate. This is stated as a
clause because both readings are defensible and an implementer choosing the other one changes what
the operator sees on every rate-limited run.

**MC3 — untasked spend is bucketed by role, in its own field.** `CanonicalBudgetUsage`
(`src/convergence/pathology/types.ts:66-73`) gains `perRole: Record<string, number>` carrying the
tokens of calls with `taskId: null`, keyed by `payload.role`.

**Not reserved keys inside `perTask`.** `exhaustedDimensions` iterates *every* `perTask` key
(`budget.ts:124-127`) and emits `task_tokens:<key>` for any that crosses `maxTaskTokens`. A role
bucket there would be enforced as if it were a task, and would then exhaust a dimension that does not
exist. A separate field makes that inexpressible rather than merely excluded.

**MC4 — a missing or non-string role is bucketed, never dropped.** Such a call goes to the key
`"unknown"`. The item is about folds that lose data; a fold that drops the rows it cannot classify has
the same defect in a smaller place.

**MC5 — the accounting invariant, over the inputs a token counter can produce.** For any event set
whose per-call token counts are **non-negative integers and whose running total stays within
`Number.MAX_SAFE_INTEGER`**, `sum(perTask) + sum(perRole) === runTokens`. This is the clause that
makes "no tokens are lost" checkable rather than asserted, and it is why `perRole` holds **only**
untasked calls: if it held all calls the sum would double-count and the invariant would have to be
weakened to an inequality, which observes nothing.

**The domain is stated, not assumed** (revision 2, after round 1). Revision 1 said *"for any event
set"* and the round-1 reviewer falsified it with `inputTokens: 1e16` plus two one-token calls:
`1e16 + 1 + 1` rounds to `1e16` while `1e16 + 2` does not, so the two groupings differ by 2. That is
a property of IEEE-754 addition, not of this change — **any** implementation that sums the same values
in two groupings has it, including the code at base, and the only escape is exact arithmetic. The
honest clause names its domain.

**What the domain does and does not guarantee, corrected in revision 3.** Revision 2 argued the domain
"contains every input a provider can produce". The round-2 lane checked and that is too strong:
`maxRunTokens` defaults to `null` with no upper bound (`src/domain/config.ts:124-128`), and
`OpenAICompatProvider` (`src/providers/openaiCompat.ts:78-99`) trusts a provider's token numbers
without a safe-integer check. So an out-of-domain value is *reachable* by a malformed or hostile
provider response, not merely unimaginable. The claim that survives is narrower and is the one made
here: within the domain the equation is exact, and outside it **no** grouping-independent sum exists
without exact arithmetic, so the defect is not repairable at this seam. A fold is not a validator;
bounding token counts belongs where they enter the system.

**The clause is total over *keys*, which is not a domain restriction.** A task id or role of
`__proto__` assigned into an object literal sets the prototype instead of creating an own key, and
the tokens vanish; `constructor` reads back as a function and the accumulator becomes a string. Both
keys arrive from an event payload, so neither is unreachable by construction. The accumulators are
therefore `Map`s, converted once with `Object.fromEntries`. This applies to `perTask` as well as
`perRole` — not scope creep, because MC5 sums `perTask` and is false without it. The round-1 reviewer
found this; no fixture would have.

**MC6 — `BudgetSnapshot` does not gain `perRole`.** `budgetSnapshotFromUsage` (`budget.ts:92-99`)
feeds the broker's enforcement view (`src/broker/quota.ts:17-23`). `perRole` is an **attribution**
record, not a limit; putting it where limits are read invites a role cap that nothing in the config
defines. The fold is the diagnostic surface; the snapshot stays what it was.

**MC7 — the digest carries the tail as a field, and the regex is deleted.** `DigestEntry`
(`loopWindow.ts:37-46`) gains `readonly tail: string | null`. A failed command's `text` becomes
`` `${argv} -> exit ${code}` `` and its output goes in `tail`. Demotion sets `tail: null`. The
`replace(/: [\s\S]*$/, "")` call is removed, not repaired — a narrower regex would still be parsing a
string the code itself just composed.

**MC8 — the cap and the emission use the composed form.** `buildLoopDigest` filters on
`estimateTokens(entry.text)` (`:75`) and `render` joins `entry.text` (`:90`). Both must use the
entry's **rendered** form, tail included, or the cap would be computed against a string shorter than
the one emitted. This clause exists because the token cap is the one thing in this file with a
correctness consequence.

**The sort's tie-break is excluded, revision 3, and the exclusion is the point.** Revision 2 also
required `a.text.localeCompare(b.text)` (`:77`) to use the composed form. **Both lanes independently
showed that clause cannot be observed**: the comparator's earlier arms are `priority` then `seq`, and
`seq` is unique per entry, so the lexical tie-break is unreachable through `buildLoopDigest` no matter
which string it compares. Swapping it to `entry.text` passes all 916 checks.

The code still uses the composed form there, because consistency costs nothing. But **no clause claims
it**, and none should: per the addendum recorded with P1.10 in `docs/ledger/PHASE-C.md`, the answer to
an unobservable clause is to delete the clause, not to grep for it or to write a check that reaches a
branch production cannot. The round-2 lane, which raised it, said the same in the same words.

**MC9 — no other behaviour changes.** No change to what is classified as a failure, to section
priorities, to the cap, to `runTokens`, `knownRunUsd`, `unknownCostCalls`, `sourceWatermark`,
`usageConflict`, or to `exhaustedDimensions`' behaviour on real task ids.

## Acceptance criteria

The plan names five checks. AC1–AC5 are those five; AC6–AC9 are added because three of the five are
satisfiable without observing the clause they belong to.

**AC1 — the membership MC2 defines, with both halves distinguishable.** A run mixing one priced call,
**five** calls that reported usage without a usable price (`null`, absent, `NaN`, `Infinity`, and a
string), and **two** that reported no usage at all, yields `usd` equal to the priced amount and
`unpricedCalls: 5`.

**Revision 4, after the v3 re-check.** Revision 1's AC1 used one call of each kind and asserted
`unpricedCalls: 1`. That number is produced by the right classifier *and* by two wrong ones: one that
**swaps** the classes — counting usage-less calls and ignoring a non-finite price — and one that
recognises only a **literal `null`** price, missing `undefined`, `NaN` and infinities. Both survived
every check. The counts now differ between the classes (5 against 2), so a swap is visible, and every
non-finite shape MC2 names is present, so a narrowed predicate is visible too.

**Revision 5, after the re-check's second round.** Killing two wrong classifiers did not establish the
predicate; three more survived. The fixture now separates each:

| Surviving classifier | Why it is plausible | What separates it |
|---|---|---|
| `if (!cost)` after parsing | the usual nullable-number shorthand | a priced call with `costUsd: 0` — which the **free tier actually reports** |
| `cost === null \|\| cost < 0` | `finiteNonnegative` is the predicate the fold next door uses | a priced call with a negative cost |
| deduplicate by `callId` | `foldModelCallUsage` deliberately does deduplicate | two unpriced events sharing one `callId` |

So AC1's fixture is three priced calls (`0.25`, `0`, `-0.05`), **six** unpriced events of which two share
a `callId`, and two usage-less calls: `usd` is `0.20` and `unpricedCalls` is `6`.

The error this phase has now made in five items: **a criterion that names a member of a set does not
observe the set.** Its sharper form, learned here: **two classes with equal counts are
interchangeable, and a predicate is only observed by inputs that sit on each side of every boundary it
draws** — zero, negative, non-finite, absent, and duplicate were five boundaries and the fixture had
inputs for one.

**AC2** Untasked calls appear in `perRole` under their `payload.role` — at least two distinct roles in
one fold, so the check cannot pass by bucketing everything into one key.

**AC3** `perTask` contains no key that is not a task id: for a fold over untasked calls only,
`Object.keys(perTask)` is empty, and no key equals `"unknown"`, `"__council__"`, or any role name.

**AC4** A `model.call` with `taskId: null` and **no** `role`, and one whose `role` is a non-string,
both land in `perRole["unknown"]` and their tokens are counted.

**AC5** A digest containing a demoted failing `git commit -m "fix: x"` still contains `-> exit 1`. At
base it contains `git commit -m "fix` and no exit code.

**AC6 — the invariant (MC5).** Over a mixed fold — tasked and untasked calls, two roles, one
role-less — `sum(perTask) + sum(perRole) === runTokens`. Asserted as an equation, not as three
separate totals: the equation is what fails if a future change starts dropping a row.

**AC6b — the invariant over generated inputs, not chosen ones (revision 2).** The same equation, under
`fast-check`, over arbitrary arrays of calls with arbitrary task ids and roles — the generator draws
explicitly from `__proto__`, `constructor`, `toString`, `hasOwnProperty` and the empty string as well
as arbitrary strings — and integer token counts inside MC5's domain. 300 runs.

This exists because AC6 is a fixture and a fixture only contains the shapes its author thought of.
`__proto__` reached this fold because a reviewer generated it, and the same reviewer's finding is why
the clause now has a property check rather than a longer list of hand-written keys.

**AC6c — the prototype keys, named directly.** A fold over calls with `role: "__proto__"`,
`role: "constructor"` and `taskId: "__proto__"` puts all three in **own** properties with the right
token counts. Asserted by comparing `Object.entries`, not by looking keys up: reading
`perRole["constructor"]` on a plain object returns something truthy whether or not the key was ever
set, so a lookup cannot tell a recorded key from an inherited one. Comparing the entry list also pins
the full own-key set, which a per-key assertion does not.

**AC7 — `exhaustedDimensions` is not fed roles (MC3).** A fold whose untasked role spend exceeds
`maxTaskTokens` produces **no** `task_tokens:` entry. This is the criterion that discriminates
`perRole` as a separate field from `perRole` as reserved keys: the reserved-key implementation passes
AC2, AC3 and AC6 and fails this.

**AC8 — the cap is computed on what is emitted (MC8).** A digest whose entries have long tails
respects `cap`. Specifically: an entry whose `text` alone is under the cap but whose `text` + `tail`
exceeds it must not be emitted whole. A `render` that joins the tail while `buildLoopDigest` measures
`text` alone passes AC5 and fails this.

**AC9 — `unpricedCalls` reaches the operator (MC1).** The rendered observe view contains the count
when it is non-zero, and does not when it is zero. A return value nothing displays is not a fix.

**AC10 — mutation.** Each of the following must fail a **named** check: reverting the `taskId !== null`
guard so untasked calls are dropped again; bucketing untasked spend into `perTask` under a reserved
key; dropping role-less calls instead of bucketing them as `"unknown"`; counting usage-less calls in
`unpricedCalls`; keeping the demotion regex; measuring the cap on `text` without `tail`; returning
`unpricedCalls` without rendering it. Results recorded in the run ledger.

## Out of scope

- Any change to how `costUsd` is produced, or to provider pricing. This item reports the absence of a
  price; it does not acquire one.
- Enforcing a per-role budget. MC6.
- `unknownCostCalls`, which is already correct and is the fold's own version of the same information
  at a different granularity. It lists call ids; `unpricedCalls` counts events in a different fold in
  a different file. They are not merged here, and the contract does not claim they agree: they have
  different denominators, since `foldModelCallUsage` deduplicates by `callId` and `usdUsage` does not.
- The digest's section priorities, cap value, and eviction order.
