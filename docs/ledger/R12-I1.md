## SAT: why the external project does not finish

Every SAT attempt since the path was fixed went the same way. Codestral (attempt 1) wrote Jest-style tests without reading the project's, or answered in prose. glm-4.6v (attempt 2) read `src/args.ts`, wrote a 5.7 KB test file, ran `npm run test`, and was fixing its imports (`ReferenceError: test is not defined`; the project uses `node:test`) when it reached 96,000 tokens, after 8 to 10 turns. The whole-suite output is 403 lines, about 9.5k tokens, of which 370 lines are passing tests. It stays in every later request, and the allowlist offers only the whole suite (`node --import tsx --test <file>` is refused). Nothing loops; the cap is the owner's, and the terminal code says so. `run_01m3dwz31fzbv547k3v0vh` on the final build went the same way: codestral wrote Jest tests and tried `npm install jest`; glm read `src/args.ts`, wrote the file, patched it three times, rewrote it, and had run the suite twice at 106k tokens. Three ways out are owner decisions, not defects:

- raise or unset `maxTaskTokens`;
- let the allowlist run one test file for `node --test` projects;
- fold passing-test lines in command output while keeping failures verbatim.

## Open

- Reviewer calls carry `taskId` without `taskAttempt` and are charged to the bare task key: 11k to 14k tokens over four rounds here. Nothing is refused at this size, but a large project with many rounds would reach `maxTaskTokens` on review calls.
- llama-3.1-8b reports affirmations as findings every round. They are now REJECTED without an investigation, but each still costs a debate.
- **Investigations cannot run a reproduction on these fixtures.** An investigation may only add files, and the allowlist admits only the project's check, `npm run test`, which runs the fixed `tests/add.test.mjs`. So a reproduction in a new file is never executed. In `run_01m3dt06gve60z50cqwgam` the worker added `check_add_type.mjs`, named `npm run test`, the engine re-ran it, it passed, and the finding was REJECTED. The claim was false, so the verdict was right, but the command never ran the reproduction. In `run_01m3dvhgf6yapa3cvhvcnx` codestral could not finish at all: it edited the tracked test, was told to use a new file, and its `./reproduce.sh` was refused. The engine can only reject this way, never confirm, so it cannot create a false blocking finding, but it can hide a real one. The way out is the same owner decision as for SAT: let the allowlist run one named test file (`node --test <file>`).
- A reviewer's canary is asked only when a round is about to be recorded clean, so a failing reviewer can serve several rounds first (seven in `run_01m3dt06gve60z50cqwgam`).
- Workers read "make add return the sum of its arguments" differently: `run_01m3dwdp5azm7fnhtva4fg` made `add` variadic on the nothing-to-do fixture, and `run_01m3dwz2xd2gj9bn7ar0tj` changed nothing. Both are defensible readings, and neither is a false finding.
