# R11 I7 — orphans, the sidecar, and readResource

**Date:** 2026-09-25. C3 is reversed: every recorded `candidate.compared` used `empirical`, and `verifier.backend "sidecar"` now fails the config parse with an explicit message. `decomposeCriteria` lives in `src/verify/criteria.ts`. `createVerifierStrategy` only builds the TypeScript judge or refuses to build `empirical` without the broker.

Removed: `FactsService`, `buildSupervisorView`, `CleanRoundTracker` (`preferRotatedEnsemble` stays), `executionEvidenceIsSufficient`, `EventLog.causalChain`, `buildFacadeReportInput`, CodeGraph (`codegraphCli`, `composite`, `probe`, `fixtures/bin/fake-codegraph`), the Python sidecar, `ProtocolRegistry.readResource`, and the `typescript` / `react-native` skills. The anti-rationalization table is in the body of `base-engineering-policy`, which every role already receives. ADR-0001 records the seam that stayed: `RepositoryIntelligence` and `BasicIntel`.

Not removed, and why:

- `REJECTED` and `CANCELLED` task states. Nothing has emitted them, and production treats them as the way a task ends without integrating.
- Unread config fields and the event types `checkpoint.rolled_back`, `shell.command`, `budget.updated`. They are still named by readers (pathology sampling, the semantic log). Deleting the names without those readers is a second change.
- The duplicate `RunHead` type. Both copies are still live; merging them is a rename, not a deletion.

The worker-pack cap test moved from 530 to 620 tokens because the inlined policy is part of the protected section.
