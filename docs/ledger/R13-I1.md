## What changed, by phase

**Phase 0 — shared ground.**
- 0.1 `detectFramework` reads the runner from the test script's own segment (flags between `node`
  and `--test`, compound scripts); dependencies and configs decide only when no script names a
  runner; a package name is never read as one. `ProjectProfile.testRunner.fileArgv` is the argv
  that runs one file. SAT's `node --import tsx --test "src/**/*.test.ts"` → `node-test`,
  `["node","--import","tsx","--test"]`.
- 0.2 One report for node:test (spec), vitest and jest: each failure classified — `assertion`,
  `reference_error`, `syntax_error`, `module_not_found`, `error`, `file_failed` (a file whose
  process died with nothing printed) — with its top frame; `processEnd` separates killed, timeout,
  aborted. Moved to `src/domain/testReport.ts` in 2.3 so worker tools can read it;
  `src/project/parsers.ts` re-exports it and the silencing gate is unchanged.
- 0.3 `test_file` policy rule (owner C): the runner's argv plus exactly one relative test path in
  the worktree — no `..`, no pattern, no option.

**Phase 1 — honesty.**
- 1.1 Evidence contract (`src/domain/evidence.ts`, `src/engine/evidenceJudge.ts`): demonstrated
  only by a failing test the runner reports inside the reproduction, not a load error in the
  reproduction's own file, and with the control run passing; refuted only when the reproduction
  is seen to run; otherwise not examined with one of the council's reasons. One added test file
  runs alone through the project's runner whatever the worker named; any other command gets a
  control run without the added files. Retryable reasons are written into the task for the next
  attempt; killed, timeout and environment are not retried. `classifyReproduction` is gone.
- 1.2 `createTaskFromValidFinding` refuses any validation not `demonstrated` by the system. Debate
  decides relevance, never existence: judge VALID → investigation brief; judge REJECTED closes only
  an advisory finding, as `debate_dismissed` (owner B); transcripts are not evidence refs.
  Runtime scenarios are context (UNCERTAIN), not verdicts. `legalDebateValid`, the corpus-kind
  helper and the validator's dropped investigation task are deleted.
- 1.3 Disposition tally on every clean round and in every DONE summary. A blocking finding no
  execution settled ends `DONE converged_with_unexamined` naming it and why (owner A), not
  NEEDS_HUMAN. A failed fix task names the finding it came from.
- 1.4 `no_change_required` checks the task's own acceptance on the base (owner D): a path an
  acceptance line names must exist; the planner's structured checks (`file_exists`, `test_file`,
  `command`) run there. The worker is told in-loop.

**Phase 2 — the worker surface.**
- 2.1 Hashline edits replace `apply_patch` (owner: replace): `read` shows `N:hh|text`; `edit`
  replaces/inserts/deletes by anchor; stale anchors, overlaps and no-ops are refused; a third
  identical no-op gets STOP.
- 2.2 Test-API write guard: in a node:test project, a test file calling `describe`/`test`/`expect`
  without importing them, or importing vitest/jest, is refused at write/edit time.
- 2.3 `run_command` leads a test run with the runner's report and folds passing lines; unknown
  long output keeps head and tail; the whole output stays readable by `fullOutputRef`.
  `outputCompressor.ts` (never wired) is deleted.
- 2.4 Superseded `run_command` results and stale `read`s are stubbed in the worker window.
- 2.5 Test-writing tasks get the head of an existing test file for the project's runner.
- 2.6 `budget.maxAttemptTokens` (`maxTaskTokens` is its earlier name); unset is no cap (owner E);
  review calls carry `subjectTaskId`, not a budget key.

**Phase 3 — findings and reviewers.**
- 3.1 Removed-line quotes are valid citations; one bad ref no longer voids a finding; a void
  citation counts `citation_unverifiable`; duplicates need the same checkpoint; validations that
  ran nothing say method `none`.
- 3.2 Reviewer admissibility rule in every reviewer's system prompt; emission guard per reviewer.
- 3.3 Mutant sweep (`scripts/mutate-touched.mjs e8a6526 --only <verdict files>`): 36 conditions,
  12 surviving flips; 2 equivalent (defensive guards in `engine/dispositions.ts`), 10 killed by
  new tests; re-sweep of the three files: **24 conditions, 0 survivors**. The blinded corpus
  re-measure did not complete on free models: 36 of 288 cells, 252 transport failures (the
  shared 20/min allowance) — no reading, not a zero.

**Phase 4 — cost and reliability.**
- 4.1 `node_modules` cached per lockfile/manager/Node/platform under `<home>/dep-cache`, cloned
  into checkouts (`cp -c` on macOS).
- 4.2 Worker calls fall back along the router's next models on a rate limit. **Fixed after the live
  smoke:** an account-scoped limit (every `openrouter_free_tier_*`) falls back only to another
  provider, and OpenRouter's `X-RateLimit-Reset` becomes `retryAfterMs` when under two minutes.

**Phase 5 — live tier.**
- 5.1 Pair generator: 10 seeds, weak test in the fixture, oracle outside; parser-found mutants;
  a pair is kept only when the weak test passes and the oracle fails by assertion. 20 pairs over
  all 10 seeds.
- 5.2 Trials recorded on their runs; report per arm with exact one-sided 95% bounds. A DONE that
  claims correctness (`converged`, `no_change_required`) with the oracle failing is a silent miss.
- 5.3 SAT offline replay (`fixtures/sat-shape`): Jest file refused, node:test file run alone, suite
  run once with output under 40 lines, DONE converged under the budget.
- 5.4 See "Live tier" below.

**Phase 6.** 6.1 Worker advisor behind `agent.advisor` (default off).

## Live tier

`scripts/live-pairs.ts`, own home `~/.polish-experiments` (never `~/.polish`): free_only, every
council model a `:free` route from OpenRouter's live catalogue, `maxRunUsd = 0.01`, no attempt cap.

What the live tier found, each fixed and tested before the next attempt (`r13-smoke` …
`r13-live-4` are the attempts; their trials are in the experiment store and are not the
measurement):

1. `maxRunUsd = 0` reads as already spent: the run paused before its first call (script: one cent).
2. `minimax/minimax-m3:free` is no longer free (404 "unavailable for free"): the owner's pinned
   council had one working free model left (script: council from the live catalogue).
3. The 4.2 fallback walked free models on one OpenRouter account, all behind the same 20/min
   allowance (`640831f`: account-scoped limits fall back only across providers; the reset time
   from `X-RateLimit-Reset` is waited out when under two minutes).
4. With no eligible worker the factory called a model named `default` (400) (`69a0c81`: says
   `PROVIDERS_UNAVAILABLE`). A free judge voted needs_human for "no baselineEvidence" on a green
   base (`69a0c81`: the payload carries a one-sentence `baselineVerdict`).
5. **A 403 about one model switched the whole provider off.** `thinkingmachines/inkling-small:free`
   answers 403 "only available on agentic harnesses"; read as `auth`, it disabled OpenRouter for
   the daemon's lifetime, so every later run had no worker model (`7cb1ed4`: only a 401 disables a
   provider; a 403 that is not about the key is that model refusing). This predates R13 and can
   have affected the owner's runs.
6. **Money under free_only.** `google/lyria-3-clip-preview` advertises 0/0 and billed **$0.04** for
   one debate call, on the owner's OpenRouter key — the only spend of the whole live tier. The
   one-cent run cap stopped the run after that call. Fix (`a31e2ef`): a model whose output is not
   only text has no stated price; a call that bills a model advertised free takes its price away.
7. **Hot loop.** A spent run budget outside the council phases was retried at tick rate: 26,616
   `run.driver_failed` events in 36 minutes (`a31e2ef`: the run ends `FAILED budget_exhausted`).

What the trials that ran show so far: the one planted defect a worker reached was fixed (oracle
passes on the run branch), and the run still refused DONE — `review_unverifiable`,
`insufficient_families: 2 of 3 (dots-studio, nvidia)`: the free catalogue has too few families
with a strict review schema once the author's family is excluded. No trial ended with a
demonstrated finding on correct code, and none ended DONE with the defect in the code. With no
DONE yet, those zeros bound nothing; the family requirement was not relaxed to get one.

Measured run: `r13-live-5`, 20 pairs x 2 sides, started after `a31e2ef`; resumable with
`pnpm exec tsx scripts/live-pairs.ts --pairs 20 --arm base --experiment r13-live-5`. The report
is `projectExperiment("r13-live-5", …)` over `~/.polish-experiments/polish.db`.
