# P2.2 — Non-inferiority baseline (quality only)

**Status:** FROZEN, revision 1. **Base:** HOST `0d80cb0`.
**Plan reference:** `docs/PLAN.md` §4 P2.2. **Goal:** G2 quality non-inferiority.
**Gates:** P3.2 and P3.3. **Process:** v3.

This item measures and writes a ledger file. It changes no production behaviour. As with P2.1 the
method is frozen before the count is taken, because the count decides whether the gate is vacuous.

## What this set is and is not

It governs **quality non-inferiority only**. The cost denominator moved to the review round in
`docs/PLAN.md` §1 and is not measured here. A token figure may appear as metadata; it is not a
condition of this gate.

## Mandatory clauses

**MC1 — what an entry is, stated so it cannot be inflated.** An entry is admissible only if it is
a **committed scripted scenario** that does all three of:

1. creates a run from a **fixture mission** — the fixture is named per entry;
2. drives that run through the **production phase drivers** with `ScriptedProvider` cassettes or
   the daemon RPC surface, not by patching state into the store; and
3. asserts a **named terminal state for that run**.

A test that asserts a helper throws, that exercises a projection or a domain function without
driving a run, or that only inspects an intermediate phase, is **not** an entry. Each admitted
entry records its file, its test name, its fixture, the asserted state, and the models the
`ScriptedProvider` is configured with.

**Terminal state** means a state the run does not leave under continued ticking: `DONE`, `FAILED`,
`NEEDS_HUMAN` with no pending answer, or an explicitly asserted "does not reach `DONE`" outcome
together with the phase it actually rests in. A mid-run assertion such as control `STOPPED` then
`RUNNING` is **not** a terminal state and is recorded as `not_terminal(reason)` rather than
admitted. This is the clause that decides whether the floor is met honestly, so it is applied
before any counting.

**MC2 — the historical half is enumerated, not summarised.** Every task in `~/.polish/polish.db`
that reached `INTEGRATING` is listed with run id, task id, checkpoint hash and recorded token cost,
measured read-only by the same discipline as P2.1 (`readOnly: true`, never `openDb`). Each is
marked replayable or `not_replayable(reason)`, and the excluded count is stated. A historical entry
is replayable only if its mission and task contract can be re-run against the fixture with
cassettes that exist; the absence of cassettes is a reason, not a judgement.

**MC3 — stability is measured, not assumed.** Every admitted entry is executed **3 times** and must
reach the same terminal state in all 3. The command, the repetition count and the observed states
are recorded. An entry that varies across repetitions is recorded as `unstable` and is **excluded
from the floor**, because a gate that demands "the same terminal state in all 3 repetitions" cannot
be discharged by an entry that does not have one.

**MC4 — the floor, and the verdict when it is not met.** The set must hold **at least 5 replayable
entries, of which at least 2 reached `DONE`**. Below that, P2.2 reports
**`inconclusive — insufficient replay corpus`**, and P3.2 and P3.3 report `inconclusive` rather
than passing. At or above it, the quality gate is evaluable and says so.

**MC5 — two bars that survive a met floor, because a met floor is not a licence.** Both are
recorded in `replay-set.md` as conditions, not caveats.

1. A scripted entry is **barred from `docs/PLAN.md` §1's cost arm**: `ScriptedProvider` reports no
   real spend.
2. Frozen completions test **orchestration, not model output**. A change that alters what a model
   is asked or what it returns is `inconclusive` here **regardless of the floor**, because the
   cassettes would miss and the set would be testing a different request. P1.2 and P3.2 are named
   examples of such changes.

**MC6 — the quality gate is stated as a rule, not as a sentiment.** A change may replace an
existing path only if every replayable entry reaches the same terminal state in all 3 repetitions.
The phrase "at equal or lower cost" is absent by decision: cost is §1's gate on its own
denominator.

**MC7 — no scope beyond P2.2.** No production change, no new E2E scenario written to inflate the
count, no change to P2.1's instrument, and no cost measurement. If the floor is unmet, the answer
is to record it, not to author entries until it is met.

## Acceptance criteria

1. `docs/ledger/replay-set.md` exists and lists every admitted entry with all five fields of MC1.
2. Every candidate scenario in `src/e2e/` is dispositioned — admitted, `not_terminal(reason)`, or
   `not_replayable(reason)` — with none silently omitted.
3. The historical `INTEGRATING` tasks are enumerated per MC2 with their excluded count.
4. The 3-repetition result is recorded per entry, with the exact command.
5. The verdict is stated, with the replayable count and the `DONE` count that produced it.
6. MC5's two bars and MC6's rule are in the file.
7. The consequence for P3.2 and P3.3 is recorded, consistent with `docs/PLAN.md` §5.
