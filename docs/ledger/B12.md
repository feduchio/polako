**Class default:** PHASE_REQUIRED  
**Plan:** Fable §17 B12; §1 runtime validation; §5 run state machine.  
**Prompt:** RuntimeValidator/Scenario/Evidence; auto|required|off; result not only baseline; corpus integration.

Implemented **early** so B2/B6/B10 can consume it. Number kept as B12.

## Required behavior

1. Types: `RuntimeValidator`, `RuntimeScenario`, checkpoint-bound `RuntimeEvidence` (additive `checkpointHash` on domain evidence if missing).
2. Config: `runtime_validation.mode: auto | required | off` (default `auto`), `level: smoke | affected | full`.
3. Discovery in `DISCOVERING_PROJECT` classifies capability: `AVAILABLE_SAFE` | `AVAILABLE_UNSAFE` | `UNAVAILABLE` | `NOT_APPLICABLE`.
4. `auto`: use a safe local reproducible path when it exists; otherwise skip without blocking. `required`: DONE forbidden without successful **final** runtime validation. `off`: do not run.
5. Safe side-effect policy: no destructive external effects (prod DB, payments, external APIs) without explicit confirmation. Unsafe available ⇒ not used in `auto`.
6. Evidence is bound to a checkpoint hash. Baseline evidence cannot be reused as final evidence. If `runtime=required` and evidence checkpoint ≠ final checkpoint ⇒ DONE impossible.
7. Minimal validator: local command / fixture / CLI / deterministic scenario script. No RN/browser platform in Phase B (that is C11).
8. GATING: affected/small scenarios allowed. INTEGRATING: affected + core smoke when available. CONVERGENCE: full required corpus.
9. Validated runtime regression scenarios join Mission Acceptance Corpus; later checkpoints must keep passing them.
10. Scheduler lane `local.runtime` with concurrency 1 (additive to Phase A `LaneSchema` / `LaneLimitsSchema`).
11. Production discovery driver records runtime capability; production convergence consults final evidence.

## Prohibited shortcuts

- Runtime only at start, then DONE on old evidence.
- Universal UI automation.
- `required` mode that still DONE on skip/unavailable.
- Treating tests-pass as runtime evidence.

## Deterministic evidence

- auto + safe fixture script → evidence with checkpoint hash.
- auto + no safe path → skip, not fail.
- required + no validator → cannot DONE.
- required + evidence for baseline hash after a new checkpoint → rejected as stale.
- required + final scenario fail (tests green) → cannot DONE.
- Corpus retains a validated scenario and re-runs it on a later checkpoint.
- `pnpm check`.

## Global invariants

Runtime as first-class verification; Mission Acceptance Corpus; baseline-relative (runtime baseline is recorded, but final is required separately); trusted-project / safe side effects.
