## What the reviewers found, and what it says about where the risk was

Both blocking defects were in `recentlyRateLimitedReviewModels`, not in the skip logic. The skip itself
was correct from the first commit; what was wrong was the meaning of the row it writes.

`recentlyRateLimitedReviewModels` has exactly two channels through which a model stops being excluded:
the `latest` map, and `completedKeys`. A skip row is `completed: true`, so it satisfied both, and a
model that had returned 429 was un-excluded by a row that never reached a provider. Three production
call sites consume that helper (`src/daemon/composition.ts:394`, `:558`, `:610`), so the effect was
that the next round would call the rate-limited model again.

Round 1 found the `completedKeys` path. My repair closed it, and I wrote AC14 for it — **in the wrong
order**. The `rateLimited` set is per-tick, so the reachable sequence is 429 first, skip later, which
lands in the `latest` map; AC14 seeded skip first, which only ever exercises `completedKeys`. Round 2
caught that, in both lanes independently, with the same reproduction. Both guards are necessary and
neither substitutes for the other: reviewers demonstrated in round 3 that removing either one fails a
named assertion.

Second observation on my own work: two of my assertions were vacuous before a reviewer saw them, and I
caught both by mutation rather than by reading. Revision 2's AC5 claimed to discriminate MC2 but both
implementations passed it. Revision 4's AC9 claimed to test rehabilitation but the guard could be
removed with AC9 still green. Mutation testing found what reading did not, twice.

## Accepted consequence, examined twice and recorded rather than fixed

A skipped execution counts as a completed review in clean-round accounting
(`src/convergence/record.ts`), anti-fake-DONE (`src/convergence/antiFakeDone.ts`), the final report and
the economics fold, even though no adversarial provider ran. The GPT lane raised this in round 1,
re-examined it in round 3 at my request, and both times concluded it is an accepted consequence of the
frozen contract rather than a defect: MC4 mandates `completed: true` — without it `missingAxes`
requeues the axis forever — and the row keeps its truth marker in `error`. It cannot fabricate an
unreviewed checkpoint, because the predicate requires real completed clean evidence from the other axes
first.

It is still a wording problem in operator-facing surfaces, and it is the reason
`docs/PLAN.md` §1 forbids enabling this flag by default until the quality gate passes.
