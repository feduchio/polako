## The blocker that was not one

`docs/PLAN.md` blocked this item on an *"unexplained budget resolution"*: a corrupt facade apparently
yielding `{budget: "run_usd", limit: 1}` while the daemon-wide budget resolved to 100.

It was a misreading. `keeps the sound half of a run's persisted budget when the other half is corrupt`
writes `facade.json` **twice**, and the second write — `{ ...metadata, budgetTokens: "lots" }` over the
*original* metadata — restores `budgetUsd: 1`, which is the **sound** half the assertion is about.
`limit: 1` was always correct. The previous session read the first write while reasoning about the
second scenario.

The real obstacle was the one the handover gave for the other three cases and which applies to all
four: **they restart repeatedly on one run and rely on spend resetting to zero.** That is the defect
this item removes, encoded as expected behaviour. Adapting them — a fresh run per restart — was the
whole difficulty, and AC7 exists so that adapting could not quietly become deleting. Grok audited the
corrupt-shape counts and confirmed 6/6, 5/5 and 2/2 across the three facade cases, with no assertion
weakened.

## One mistake, three times, in one item

Every GPT round found the same error wearing a different coat, and it is the error this whole phase
keeps producing:

| Round | What was written | Why it observed nothing |
|---|---|---|
| 2 | AC11 mutated `runTokens` and `perTask` | the copy is shallow **per field**; `unknownCostCalls` was its own opening |
| 3 | AC11 named all four fields | `runUsd` was written as `0` into a fixture where it was **already** `0`, and never asserted |
| 3 | the `record` twin mutated three fields | not `perTask` — and `perTask` is what per-task enforcement reads |

The general statement, now in the contract: **a criterion that names a member of a set does not
observe the set, and naming every member does not observe them either unless the fixture gives each
one a value that the regression would visibly change.** The fixture now records one priced call and
one unpriced call so all four fields hold distinguishable values.

The grid is the shape that finally worked: four fields × two surfaces (`snapshot`, `record`) = eight
single-field regressions, each required to fail a named check. GPT ran all eight and none survived.

## What Grok added, looking where GPT had not

- **The restore predicate, verified against this tree** rather than against the plan. `listActive()`
  excludes `NEEDS_HUMAN` and `STOPPED`; both are `terminal` with empty edges, `answer()` returns the
  run still in `NEEDS_HUMAN`, and `resume` maps only `PAUSED`/`PAUSE_REQUESTED`. `PAUSED` and
  `STOP_REQUESTED` **are** in the set and are restored. The plan's *"resumable = not DONE/FAILED"* is
  false here and the contract's correction holds.
- **The interaction with P1.7**, which landed immediately before. It drove two probes and found no
  ordering where a stale facade is cached before restore, or where restored spend is compared against
  the wrong cap: `limitsFor` is lazy, `restore` writes only spend, and both maps are empty in a new
  process.
- **Which new checks fail at base and which do not.** The two "do not restore" checks and the
  restore-hop hostile-key unit test pass at base — they are mutant guards, not defect-encoders. The
  five that encode the defect do fail. That distinction is worth having on the record.
