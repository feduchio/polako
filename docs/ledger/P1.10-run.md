## The escalation, which is the real result of this item

One clause consumed three rounds. MC5 said *"`reviewDrivers.ts:102` is not wrapped"* — a second
diagnostic surface on a path production does not take.

| Round | What observed MC5 | How it was defeated |
|---|---|---|
| 1 | nothing | GPT: class (c), no check observes the clause |
| 2 | one non-test file owns the string `protocol registry failed to load` | GPT: a second wrapper words its own message |
| 3 | the two `ProtocolRegistry.load(` call-site lines, verbatim | Grok: wrap the *consumers*, not the load — the line is untouched |

Each fix was a tighter grep; each was defeated by moving one step outward. There is no last step: a
wrapper can sit around the call, the statement, the function, the module, or the caller. Revision 3
was a **test-only commit**, which `docs/BVP.md` lists as a degeneration signal, and the round-3 lane
named it as one — *"Do not add AC11c. Another grep will be punched through the same way"* — while
still, correctly, recording the gap as blocking.

**The error was upstream of all three checks.** MC5 asserted a property of the *tree* — no second
wrapper exists — which quantifies over code that could be written and is exactly the unsatisfiable
shape `docs/ledger/PHASE-C.md`'s stopping rule describes. What the item needs is a property of its own
*diff*: it does not touch that file. MC5′ says that, and `git diff 7e5c013 44d4256 --
src/engine/reviewDrivers.ts` is the whole verification — complete, with no surviving mutant, because a
mutant **is** a change to that file.

So round 3's fix was a **deletion**: MC5 replaced, AC11 withdrawn, both source-scanning checks removed,
test count down from 906 to 904. The confirming lane — the same lane that had originally demanded MC5
be observed by a check — verified that the deletion took no real coverage with it, re-ran the whole
earlier mutant set against the reduced suite, and called it *"sound reformulation, not retreat"*.

The transferable rule: **a mandatory clause must be a property of the change, not of the tree.** A
clause of the form "no X exists anywhere" cannot be discharged by any finite suite; a clause of the
form "this diff does not do X" is discharged by one command.

## Three corrections to the plan, all found before designing on it

`docs/PLAN.md` P1.10 said the loader's errors *"do not carry the path"* and instructed the wrapper to
re-scan and re-apply the loader's own name/folder check.

1. **The `NOT_FOUND` root case already carried the path.** Only the mismatch, duplicate and malformed
   cases lacked it.
2. **A fourth failure class exists and is not a `PolishError`.** `ProtocolFrontmatterSchema.parse`
   throws a `ZodError`, so the planned "catch `PolishError` from the loader" would not fire at all for
   a `SKILL.md` whose frontmatter is valid YAML but fails the schema. That class is now converted to
   `INVALID_ARGUMENT` with the path and the `ZodError` preserved as `cause`.
3. **A fifth class, found by a reviewer in round 1:** `existsSync`, `statSync` and `readdirSync` are
   native file IO outside every catch, so an unreadable root escapes as a plain `EACCES` `Error`.
   Revision 1's MC1 claimed "no escape without a path" and was false when written. Now `IO_ERROR` with
   `protocolsRoot`.

The departure from the plan's mechanism — attach the path at the loader's throw sites rather than
re-derive it in the wrapper — was upheld by both lanes, which independently checked all three of its
stated reasons against this tree. One sub-reason was wrong: the duplicate-detection half of "the
re-scan is a second copy of a rule that can drift" does not apply, because that branch is dead.

## Vacuity, fourth occurrence across three items

Revision 1's AC2 said *"two folders declaring the same protocol name yield the second folder's path"*.
Its fixture produces that path — through the **mismatch** branch, because a second folder claiming a
name it does not own is a mismatch first. The duplicate throw at `loader.ts:35-37` is **unreachable**:
`readdirSync` returns distinct `entry.name`, and `meta.name !== entry.name` throws before
`byName.has(meta.name)` is consulted. The check passed and always would have; it did not observe what
its prose claimed.

Found by the GPT lane, not by the coordinator. Across P1.1, P1.2 and P1.10 every vacuous assertion has
been found by mutation or by a reviewer, and never by the coordinator re-reading the test. The dead
guard is recorded as **finding 49** rather than deleted: MC6 confined this item to diagnostics, and
removing a defensive guard needs its own argument about whether the invariant could become reachable.
