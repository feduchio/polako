# R11 I4 — one daemon, and a tick that can say it is stuck

**Date:** 2026-09-25.

`claimDaemonLock` takes `polish.lock` with `O_EXCL` before the socket is unlinked. A second process whose lock names a live pid (`kill(pid, 0)` succeeds, or fails with `EPERM`) exits with `CONFLICT`. A lock naming a dead pid is replaced. `bindDaemon` listens, and only then writes `polish.pid`.

`TickWatchdog` counts ticks longer than `max(1000ms, 10 * tickMs)`. The third in a row emits one `daemon.watchdog` on the global observations run. A shorter tick clears the count. A fourth long tick does not emit again.

`daemon.ping` now returns `tickInFlightMs`, `lastTickCompletedAt`, and `reportRenders`.

The tests kill the inverses: a second claim while this pid is alive, a dead pid being replaced, the pid file being absent during `listen`, an alarm before three long ticks, and a second alarm after the first.
