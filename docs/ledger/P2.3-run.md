## Result

**Discovery works on a second repository. Baselining does not.**

The run discovered the project and reached `BASELINING`, which is what `docs/PLAN.md` §4 asked for.
What it captured there is a baseline in which **every check failed** — `test`, `lint` and `build`,
all three `status: "fail"`, `exitCode: 1` — on a repository whose `pnpm test` had passed, exit 0,
in the same working tree minutes earlier.

The cause is not the repository. It is recorded as **finding 54** in
`docs/ledger/B-selfhost-remaining.md`: `BASELINING` runs the project's checks inside a fresh git
worktree at `~/.polish/worktrees/<run>/baseline-<run>`, and nothing installs the project's
dependencies there. A git worktree does not carry `node_modules`, so every check died on a missing
binary. The captured stderr is unambiguous:

```
sh: oxlint: command not found
WARN   Local package.json exists, but node_modules missing, did you mean to install?
```

and for `build`, `sh: unbuild: command not found`.

This is what P2.3 existed to find. `docs/PLAN.md` §2 records **0** external projects ever targeted;
the first one, in its first two phases, produced a baseline that says the project is broken when it
is not.

## What this smoke does and does not establish

**It establishes** that a second repository can be registered and discovered through the production
CLI, that `project.discovered` and a `BASELINING` snapshot are produced for it, that the check
commands are chosen correctly from `package.json`, and that runtime mode `off` does not interfere.

**It does not establish** anything about task execution, candidate gating or convergence on an
external project, and it has now positively established that baselining is broken there.

**This is not Fable D1.** No full external run is scheduled by this document or this record, and
finding 54 is recorded rather than fixed, because fixing it is production scope that P2.3's
contract excludes.
