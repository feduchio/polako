**Discovery works on a second repository. What baselining records there is not true of the
project.**

The run discovered the project and reached `BASELINING`, which is what `docs/PLAN.md` §4 asked for.
What it captured there is a baseline in which **every check failed** — `test`, `lint` and `build`,
all three `status: "fail"`, `exitCode: 1` — on a repository whose `pnpm test` had passed, exit 0,
in the same working tree minutes earlier.

**Naming the broken object precisely, because the first draft named the wrong one.** It is not
that `BASELINING` failed; the phase completed and did exactly what it is built to do. It is not
even, on its own, that dependencies are missing: running checks in an isolated git worktree is the
design, and under the policy this run used — `allowArbitraryCommands: false`, the schema default

deliberate rather than an oversight. It is **not** architecturally impossible to install:
`CommandPolicy` admits an arbitrary command when `allowArbitraryCommands` is true

nothing in the baseline path does either. What is false is the **meaning of what was stored**: three *environment*
failures persisted as the *project's* `test`, `lint` and `build` status, each with an exit code, a
duration and a `failureFingerprint`, indistinguishable in the store from a project whose suite
genuinely fails. That is recorded as **finding 54** in `docs/ledger/B-selfhost-remaining.md`.

The tree already refuses this shape one path over. `missingInstalledDependencies`
