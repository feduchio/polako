**Prompt:** parallel candidates, worktrees, independent gates, temporary integration, atomic checkpoint; stale candidate revalidation.

Phase A already contains library primitives `runCandidatesParallel` and `integrateWinner`. B2 is **not** closed by those functions existing. B2 must wire them into production phases `EXECUTING` / `GATING` / `INTEGRATING` with events, task/candidate projections, and run-head advancement.

## Required behavior

1. N candidates (from config complexity) run in parallel isolated worktrees from the task `baseCheckpointHash`.
2. Each candidate gets a fresh `AgentRunner` via `workerFactory`.
3. Independent gates run on a clean evaluation checkout of the candidate commit (existing A7/A12 protected-acceptance ordering). Gate LLM review is forbidden.
4. `no_changes` / empty candidate commit is a failed coding-candidate outcome, not a winner.
5. Tournament (B3) selects a winner only among `passed` candidates. Zero survivors ⇒ task retry/BLOCKED per retry policy, not silent integration.
6. Winner integration: temporary workspace from **current run head** (not necessarily the candidate base) → merge/rebase/cherry-pick → mandatory integration gates → runtime affected validation when applicable → CAS compare-and-set of the run head. Canonical run branch is not mutated before gates pass.
7. Stale candidate (base ≠ current head) must be revalidated in the integration workspace against the current head. Failed integration does not advance the checkpoint.
8. Successful integration creates a `checkpoint` event/projection with evidence vector; run `currentCheckpointHash` updates only then.
9. Integration lane concurrency remains 1 (scheduler `integration` literal).
10. Production `EXECUTING`/`GATING`/`INTEGRATING` drivers perform this work. Stub `X→Y` drivers are not production.

## Prohibited shortcuts

- Declaring B2 ACCEPTED because Phase A `candidates.ts` tests pass.
- Integrating into the user's working tree.
- Advancing the run branch on failed integration gates.
- Reusing one worktree for two candidates.
- Skipping gates for a "trusted" candidate.
