18. Worker tool-loop replays the whole transcript, so cumulative token cost is quadratic in turns and pre-empts the contracted `agent.maxTurns` bound. `AgentRunner.runLoop` sends `messages: [...messages]` on every call (`src/agents/runner.ts:71`) after appending the assistant message (`:89`) and every tool result (`:122`), charges the entire prompt against one cumulative counter (`totalTokens += inputTokens + outputTokens`, `:90`), and passes the remainder as that call's output cap (`remainingTokens`, `:66`). Turn capacity therefore grows as the square root of the token budget, not linearly, and the per-call generation allowance shrinks monotonically as the transcript grows. Two consequences at production defaults (`agent.maxTurns` 32, `src/domain/config.ts:92`; `maxTaskTokens` null → `32_000`, `src/daemon/composition.ts:455`): the token budget binds well before the contracted turn count, so the `agent.maxTurns` knob accepted in `docs/ledger/B-bootstrap-discovery.md` is not the effective bound; and exhaustion returns `BUDGET_EXCEEDED` → `status: "failed"` (`src/agents/runner.ts:277-282`), so candidates can drop out of `COMPARING` by transcript length rather than by evidence, biasing the tournament frontier. `read` output is the dominant growth term and is never evicted, so re-reading one file duplicates it in context for the remainder of the loop. **Measured 2026-09-10** over the 6 `agent_transcript` artifacts in `~/.polish/artifacts` (fixture runs, two `:free` models, default 32_000 cap), corroborated by the 83 recorded worker requests whose `messages` array grows monotonically from 1 to 35 entries and from 209 to ~15,100 serialized characters inside a single loop. Resent history is **61.6–72.7% of all input tokens (mean 66.9%)**. Loops ran 10–18 turns (mean 14.2) and **none reached `agent.maxTurns` = 32**; 3 of 6 ended `BUDGET_EXCEEDED` at 32.4k–34.4k total tokens. Holding the 32_000 cap fixed, a flat prompt projects to 2.3× the turns at zero state overhead, 1.5× at a 500-token state block, 1.1× at 1,000 and **0.9× — a regression — at 1,500**, with break-even near 1,250. **The state schema budget is therefore a first-class acceptance criterion, not an implementation detail:** a verbose or unbounded schema makes this change actively worse at current task sizes, and the contract must cap it (the paper's reusable CTF schema is 5 fields). The shrinking per-call output allowance is live but not yet shown to truncate — the lowest final-call allowance observed was 618 tokens, in a transcript that had produced a 578-token output earlier. Sample is thin (N=6, one fixture, two small free models); the projection is a turn-count model only and ignores the paper's noise-robustness and state-recovery effects, which this data cannot measure. Reference architecture: SKILL.state (arXiv 2608.26263), bounded `(P, Σ_t, O_t)` prompt with the reasoning trace discarded after a runtime-validated state patch. That paper's stated auditing limitation does not apply here: `persistResult` already archives the full transcript to CAS (`src/agents/runner.ts:246-251`), so Polish can drop history from the context window while keeping it in the event log. Found while evaluating arXiv 2608.26263 against the tree. **Scheduled 2026-09-10** into the pause block after finding 19 and before items 11–15; contract not yet drafted. Ordering rationale and the measurement prerequisite are in *Prompt-path ordering constraints*, `docs/ledger/PHASE-C.md`.

22. The static pin guarding B-selfhost-7's MC1 does not see two ways of writing the same assignment. `service.runtime-mode.test.ts` matches `/\.runtimeValidation(\.\w+)?\s*=(?!=)/` over non-test `src/**`, which catches dotted assignment including a value wrapped to the next line, but not `config["runtimeValidation"].mode = …` and not `Object.assign(config.runtimeValidation, …)`. This matters more than an ordinary test gap because `withRuntimeValidationMode` returns the base object itself when the requested mode already equals the loaded one (`src/domain/config.ts:266`), so runs whose mode matches `polish.toml` receive `PhaseContext.config === base`. For those runs isolation rests on the guarantee that nothing writes into the base object — that is, on this pin — rather than on structure. The asymmetry is invisible to a future writer, who sees a `PolishConfig` on `ctx` and has no way to tell whether it is shared. Closure is either a pin that also matches bracket access and `Object.assign`, or an unconditional copy in `withRuntimeValidationMode`, which trades one allocation per drive for structural isolation. Raised by Claude in rounds 3 and 4 of B-selfhost-7. **Recorded 2026-09-10**, not scheduled.

23. **A verification loop can make real progress by every measure Polish has, indefinitely, without changing production behaviour — and C2 cannot see it.** Observed on this project, not hypothesised: B-selfhost-8 changed non-test source in three commits (`2ef215b`, `ad80df6`, `df24e83`, `+109/−20` lines), all within its first three review rounds, and then ran **twenty-one further rounds and twenty-four further commits, none of which touched a non-test file**, with no reviewer reporting a production behaviour defect after round 3. The budget test file reached 955 lines against that 109-line production change. `detectNoProgress` (`src/convergence/pathology/detectors.ts:88-108`) would not fire: it requires the canonical progress vector to stop improving, and here it improved on every round — a new `checkpointHash`, newly resolved blocking fingerprints, new clean-round keys (`CanonicalProgressVector`, `src/convergence/pathology/types.ts:29-37`). `detectStyleOnlyGrowth` (`:141-161`) is the nearest analogue and is also blind to it, because it classifies *added tasks* by work class, not *accepted checkpoints* by what they changed. The mechanism is that the stopping rule in force — a survivable mutant is blocking — has no fixed point: for any finite suite an incorrect implementation can be conditioned on ambient state the fixtures do not vary, so each round closes one combination and creates the next; and a reviewer instruction of the form *"name an axis none of these covers"* makes a finding mandatory. Closure has two halves, and they land in different places. **C2 side:** the sample carries no classification of what a checkpoint changed, so a detector cannot be written against today's schema; it needs a per-checkpoint production-versus-test classification alongside `progress`, and then a detector that fires when a window of accepted checkpoints is entirely test-only while blocking findings keep arriving. Note the interaction with finding 18's state-schema budget — this adds a field to the sample, and `PATHOLOGY_SAMPLE_VERSION` is still `1` (`src/convergence/pathology/types.ts:8`). **Reviewer-protocol side:** the rule that acceptance is judged against a finite frozen contract, and that a constructed mutant is blocking only when it is a plausible omission rather than a branch on state it has no reason to read, belongs in the `reviewer-*` role protocols — which is finding 19's work, since nothing composes them today. **Recorded 2026-09-11**, not scheduled; the governing rule for the coordinator's own rounds is in `docs/ledger/PHASE-C.md`.

Base behaviour, untouched by B-selfhost-8 and outside its contract, which is why it was recorded rather than fixed there. Raised by Claude in round 17 of B-selfhost-8. **Recorded 2026-09-11**, not scheduled.
25. **One resolution of a run's budget, but two merge sites, so every divergence between the enforcing surface and the reporting surface is expressible and has to be tested rather than being impossible.** `DaemonService.runBudget` is a single lookup, but `applyRunBudgetOverrides` is then applied independently at `src/daemon/composition.ts:155` for the broker's tracker and at `src/daemon/service.ts:373` for `ctx.config` and thence C2. Both reviewers named this independently, and the measurement is stark: of B-selfhost-8's twenty-four test-only commits, the majority close mutants that live in exactly this seam — one side keeping a configured `null`, one side skipping the merge in the default runtime mode, one side truncating a fraction, one side answering every recovered run with the first budget it resolved. A shared resolver returning the already-merged `BudgetLimits` to both consumers would make the whole class **inexpressible** rather than merely tested, and would retire roughly a third of `src/daemon/service.budget-override.test.ts` with it. This is a production change and belongs to whichever item next touches this seam — items 9 and 19 both edit `createWorkerFactory` in the same file. Note the order: collapsing the merge without first having the tests is how the class comes back; retiring the tests without collapsing the merge removes the evidence and keeps the hazard. **Recorded 2026-09-11**, not scheduled.
