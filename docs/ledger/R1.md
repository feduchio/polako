# R1 — An account-scoped 429 is not a property of the model

**Plan:** `docs/RECOVERY.md` §3 R1, clauses 2 and 3. **Base:** `f8b8c0d`.
**Reviewer lane:** GPT (`gpt-5.6-sol-high`), one lane.

Clause 1 of the plan's R1 — wiring `rpm` from config into `QuotaTracker` — is **R1a**, a separate
item. R0's ceiling breach came from absorbing everything a single investigation turned up; this
item is scoped to the one sentence above.

## Defect (normative)

`src/engine/reviewDrivers.ts:873` records any failure of a reviewer call by adding that model to
`rateLimited` and moving to the next reviewer. Against a limit that belongs to the account, the
rotation walks the whole list and marks every model dead, then the next tick does it again. The
plan names the regression by number: **2,465 of 2,600 review executions never reached a model.**

The same shape exists on the other two paths. The council chain falls back to the next model on any
operational failure, including one that the next model on the same provider cannot escape. The
worker path has no exclusion set, but `ModelBroker` records the failure as a routing statistic, and
`ModelRouter` subtracts the model's failure ratio from its score — so nine models probed under one
exhausted account quota each carry a penalty for it (`docs/ledger/R0-run.md`, round 2 finding 1).

## Evidence that the scope is knowable

The 429 body recorded in `run_01m2h3hpe2f6f4ra1ywcg7`:

```json
{"error":{"message":"Rate limit exceeded: free-models-per-day-high-balance. ","code":429,
 "metadata":{"headers":{"X-RateLimit-Limit":"1000","X-RateLimit-Remaining":"0",
 "X-RateLimit-Reset":"1789430400000"},"limit_source":"openrouter_free_tier_daily"}}}
```

`limit_source` states the scope. Note it is `openrouter_free_tier_daily`, **not** the
`openrouter_free_tier_per_minute` of `docs/RECOVERY.md` §1.2: the period changed when the key was
funded, and a per-minute pacing window — R1a — cannot help an allowance that is already spent for
the day. Which is why this item, not that one, is the one the plan's regression number belongs to.

## Definitions (normative)

- **Account-scoped**: `limit_source` beginning `openrouter_free_tier`. Trying a different model of
  the same provider cannot succeed.
- **Model-scoped**: `upstream_provider_shared_pool`, per `docs/RECOVERY.md` R1 clause 2.
- **Unknown**: anything else, and any 429 with no `limit_source`. Treated as model-scoped, because
  that is today's behaviour and this item does not guess.

## Required end state

1. `ProviderError` for a 429 carries the scope, derived from the response, not from the message
   text. Unknown is a distinct value from model-scoped at the point of parsing, even though the
   two are treated alike.
2. **Review.** An account-scoped 429 does not add the model to the per-tick `rateLimited` set and
   does not continue the rotation: the axis stops and the driver waits. A model-scoped one behaves
   as it does today.
3. **Review, across ticks.** An account-scoped 429 recorded against an execution does not make that
   model excluded on the next tick.
4. **Council.** An account-scoped 429 does not fall back to another model **of the same provider**.
   It does fall back to a model of a different provider — that is what saved
   `run_01m2h3hpe2f6f4ra1ywcg7`'s judge, which 429'd on OpenRouter and completed on Gemini.
5. **Worker.** An account-scoped 429 is not recorded as a routing statistic against the model, so
   it cannot lower that model's score.

## Acceptance checks

1. A scripted provider answering every call with an account-scoped 429 produces **one** review
   execution per axis, not one per model. Stated against the regression the plan names: the number
   of provider calls is bounded by the number of axes, not by the number of models.
2. The same provider answering with a model-scoped 429 still rotates, and still excludes.
3. An account-scoped 429 on the second tick does not find the model excluded by the first.
4. A council chain of two OpenRouter models and one Gemini model, where OpenRouter answers with an
   account-scoped 429, calls **one** OpenRouter model and then Gemini — not both OpenRouter models.
5. A worker call that fails with an account-scoped 429 leaves `catalog.get(model).stats.failures`
   unchanged; a model-scoped one increments it.
6. Gate green at Node 24.

## Non-goals

- `rpm` pacing (**R1a**), and anything about which models are *preferred* rather than excluded.
- The 76 probe observations already in the event log, and `restoreCatalog`'s replay of them
  (**R1b**). They are the same invariant one layer down, and they are not what the plan's
  regression number measures.
- Making free routes unselectable while their daily allowance is spent. That is a routing
  preference, and no run has yet failed in a way that only it would fix.
