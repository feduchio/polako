**Status:** ACCEPTED (fix round 1)

**Prompt:** fresh independent reviewers; multiple axes; real checkpoint artifact; no previous-reviewer anchoring.

## Required behavior

1. Review starts only from `REVIEW_ENTRY_PHASES` (after integration, or clean-round re-review of the current checkpoint). Reviewers never see an unintegrated candidate as the run artifact.
2. Default axes include at least `correctness`, `regression`, `adversarial` (config may add more). `reviewersPerRound` from config.
3. Each reviewer is a fresh context: no prior reviewer transcript, no other reviewer's findings, no "already approved" hint.
4. Artifact is the exact integrated checkpoint (commit hash + diff vs baseline or vs previous checkpoint).
5. Output is structured `RawFinding`s (claim, evidence file refs, reproduction, blocking, severity, axis).
6. Every review execution is persisted: requested reviewer (provider/model), completed/not, axis, checkpoint hash, structured result artifact. Incomplete required reviewers ⇒ the round is not completable.
7. Production `REVIEWING` driver performs this. Synthesizing "no findings" without completed executions is forbidden (enforced with B6).

## Prohibited shortcuts

- One shared reviewer context reused across axes.
- Reviewing the candidate worktree instead of the integrated checkpoint.
- Anchoring prompts with previous round findings as ground truth.
- Marking review complete while required reviewers are missing.

## Deterministic evidence

- Scripted reviewers on a known checkpoint produce structured findings stored against that hash.
- Two reviewers do not receive each other's messages (prompt/transcript assertion).
- Reviewer asked to review checkpoint H cannot be recorded as evidence for checkpoint H'.
- Missing completion → round not recorded as complete.
- `pnpm check`.

## Implementation notes

- Review library: `src/review/` (`runAxisReview`, `runReviewSwarm`, `buildCheckpointReviewArtifact`). Each axis gets a fresh fenced context pack with the integrated checkpoint commit hash and diff (never a candidate worktree).
- Production driver: `createReviewingDriver` in `src/engine/reviewDrivers.ts`; registers via `engine.registerPhase("REVIEWING", ...)`. Does **not** record clean rounds or synthesize zero-finding completion (B6).
- Persistence: `ReviewExecution` entities projected from `review.started` / `review.finished` into `review_executions`; structured findings via `finding.raised`.
- `RunEngine` still defaults to A5 stubs; B9 must install `createReviewingDriver`.
